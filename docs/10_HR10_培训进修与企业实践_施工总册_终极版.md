# 0. 六个三级模块冻结

```text
HR10 培训进修与企业实践
├─ HR10-01 教师发展计划
├─ HR10-02 培训项目
├─ HR10-03 培训报名与审批
├─ HR10-04 企业实践项目
├─ HR10-05 实践过程与成果
└─ HR10-06 教师发展档案
```

六个工作区职责严格分离：

- **HR10-01 教师发展计划**：学校/学院/个人年度与周期发展需求、能力差距、培养目标、项目组合、预算和计划执行。
- **HR10-02 培训项目**：校内培训、校外培训、访学研修、跟岗研修、专题研修、进修项目等项目目录、版本、班次、师资、名额和资源。
- **HR10-03 培训报名与审批**：个人/团队申请、主管/学院/人事/预算审批、报名、候补、变更、撤回、完成确认和外部学习补录。
- **HR10-04 企业实践项目**：企业实践基地、企业、岗位/场景、实践目标、实践周期、导师、批次、匹配、派出与协议前置。
- **HR10-05 实践过程与成果**：过程记录、到岗/活动事实、证据、导师评价、学校评价、总结、成果与教学转化、异常和完成核验。
- **HR10-06 教师发展档案**：只汇总已核验的发展事实，形成培训/进修/企业实践/成果/学时学分/能力发展历史，并向 HR09/HR12 等下游提供权威 Provider。

11. 进修取得的新学历/学位是否正确交给 HR03 EducationHistory，而不是 HR10 自建第二学历表？

14. 同一个成果被多个项目引用时如何避免重复计数？
15. HR09 读取的企业实践证据是否来自 VERIFIED 事实而不是 DRAFT/SELF_REPORTED？

17. 外部 Provider/企业评价接口不可用时，系统是否明确 UNKNOWN/UNAVAILABLE，而不是伪装通过？
18. 教师个人、学院、人事、企业导师分别能看到哪些信息？
19. 跨学校、跨学院、跨人员访问是否 fail-closed？
20. 历史培训/实践数据迁移进来时，可信度与缺失证据是否明确标记？

# 2. 生产级红线

禁止：

- 用 `Employee.training = "已培训"` 或 free-text 代替正式培训事实；
- 把培训报名成功直接当培训完成；
- 把签到一次直接当完整课程完成；
- 把老师上传的结业证自动标记 VERIFIED；
- 把普通培训证书自动写成 HR09 正式职业资格；
- 把“企业实践 30 天”一个整数作为全部企业实践真相；
- 实践天数完全由教师手填且无来源、无校验、无证据；
- 企业实践没有企业、岗位/场景、目标、导师、任务、评价；
- 把访企参观 1 天与真实岗位实践 1 天当成同一质量；
- 为了满足双师条件批量伪造历史企业实践；
- 修改项目后回写污染已完成历史；
- 培训班次发布后静默修改总学时/评价标准/费用；
- 已核验 Completion 直接 UPDATE 覆盖；
- 申请退回和最终拒绝共用一个状态；
- 学院审批通过就直接消耗学校预算且无并发控制；
- 名额只有前端判断，后端不锁定；
- 候补名单在并发下超额转正；
- 老师申请自己审批自己；
- 企业导师能看到教师身份证、薪酬、家庭信息等无关数据；
- 用手机号/邮箱作为跨学校唯一自然人合并依据；
- 进修取得学历后 HR10 自建第二份学历权威；
- HR10 自建第二套请假/考勤系统；
- HR10 自建第二套财务报销/实际支付系统；
- HR10 自建第二套教务课程任务；
- HR10 自建第二套 HR09 资格认定；
- 企业实践开始前缺少安全/保密前置仍默认为合规；
- 把 GPS 持续定位作为所有企业实践强制条件；
- 上传附件生成永久裸 URL；
- 导入 Excel 直接生成 VERIFIED completion；
- 外部 Provider 超时自动 fallback 为“完成”；
- 数据源不可用时把完成学时当 0；
- 跨 tenant 复用企业导师 token；
- 测试用 mock 结果进入生产档案；
- AI 自动决定教师是否“完成企业实践”或是否达到双师要求；
- AI 自动生成不存在的实践日志/企业评价；
- 删除已完成培训/实践历史来修错；
- 未跑迁移/权限/并发/E2E 测试就切换 authority；
- 施工阶段直接合并 main。

# 3. 国家制度与产品边界


HR10 面向高校与职业院校，不能把某一个地区、某一时期政策硬编码为全国永久常量。

产品只冻结**制度能力**：

```text
Policy Template
→ Tenant Rule Pack
→ Effective-dated Rule Version
→ Development Plan / Program / Practice Project frozen snapshot
→ Historical Fact immutable
```

必须支持学校按当前适用制度配置：

- 全员培训周期；
- 专业课/实习指导教师企业实践周期；
- 年度/周期最低学时、天数或月数；
- 不同教师类别的适用规则；
- 新任教师前置实践；
- 公共基础课教师考察/调研/学习；
- 国家/省/学校专项培训；
- 企业实践基地优先规则；
- 经费来源与预算审批；
- 成果转化要求；
- 双师认定证据映射。

S0 必须核验目标学校所在省份与学校现行制度，不能仅凭本文替代法律/政策判断。

# 4. 职业学校教师企业实践制度硬边界


公开有效政策长期强调：企业实践是职业学校教师专业发展与“双师”建设的重要形式，且企业实践不是“打卡式活动”。

HR10 的产品抽象必须至少覆盖：

```text
Teacher Category
Practice Policy Window
Enterprise / Practice Base
Actual Position or Production/Service Scene
Practice Objective
Practice Content
Mentor / Responsible Person
Period / Effective Time
Process Management
Performance Evaluation
Summary / Output
Teaching Transformation
Safety / Confidentiality / IP obligations
```

规则计算必须用 PolicyVersion，不把“每 5 年”“每年”等数字写死在 Python。

# 5. 2025 企业实践项目指南对 HR10 的直接约束


2025 年底公开的《职业教育教师企业实践项目开发与实施指南》把企业实践进一步从“有无经历”推进到“项目化、岗位化、标准化、可评价”。

# 6. 企业实践基地管理边界


HR10 需要支持企业实践基地，但不要把“国家级基地”做成普通文本标签。

建议：

```text
HrDevelopmentProviderOrganization
- provider_kind
- practice_base_level
- official_reference
- valid_from / valid_to
- verification_status
- specialty_scope
- capacity
```

基地身份变化不回写污染历史项目；项目启动时冻结 provider snapshot。

# 7. 培训与进修政策能力边界


职业教育教师培训长期包含集中研修、线上/混合研修、跟岗、顶岗、访学、返岗实践、企业实践等多种方式。

# 8. 2026 职业教育改革方向校正


2026 年职业教育改革继续强调专业、课程、教材、教师、实习实训等关键要素与产业真实需求衔接。

HR10 产品含义：

- 培训需求应能从专业建设、教学改革、数字化能力、产业技术变化等来源形成；
- 企业实践应与真实岗位/技术场景关联；
- 成果应能回到课程、教材、实训项目、技术服务或团队建设；
- “参加过”不是最终目标，“形成可验证能力与转化成果”才是业务闭环。

# 16. HR10 与 HR09 边界


HR09 是资格/双师认定权威，HR10 是培训/进修/企业实践事实权威。

HR09 只能消费：

```text
VERIFIED TrainingCompletion
VERIFIED EnterprisePracticeFact
VERIFIED PracticeEvaluation
VERIFIED DevelopmentOutput
```

HR10 不做：

- 教师资格认定；
- 职业资格正式核验；
- 双师初/中/高级认定；
- 双师 RulePack。

# 17. HR10 与 HR08 边界

```text

allowed_activity_types

```

# 18. HR10 与 HR12 边界

```text

verified development outputs

```

HR12 不允许反向修改 HR10 completion；HR10 也不重算 HR12 考核结论。

# 19. HR10 与 HR07 / 协议文件边界


企业实践可能涉及实践协议、保密、知识产权、安全承诺等法律/管理文件。

冻结原则：

```text
HR10 owns: why / where / what / when / who / evaluation / output
Agreement provider owns: legal document body / signature / version
Documents owns: file storage/security
```

若 HR07 的 Agreement 服务被扩展为通用人员协议，可引用 `agreement_id`；否则通过 `AgreementProvider` 接口，不复制合同引擎。
