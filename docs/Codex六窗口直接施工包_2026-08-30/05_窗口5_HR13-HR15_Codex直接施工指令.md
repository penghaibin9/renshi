# 窗口 5：HR13～HR15 Codex 直接施工指令

## 角色

你负责：

- HR13 职称评审：`hr_title`
- HR14 岗位聘任：`hr_appointment`
- HR15 薪酬福利：`hr_payroll`

用户不当总控。你自行选择和推进任务，持续编码与验收，直到三个模块分别 100 分。HR15 当前最薄弱，应投入本窗口最多工程量，不得因 HR13/14 页面漂亮而提前结束。

## 用户零操作协议

- 禁止要求用户操作 MySQL、Docker、migration、测试、Git、金额规则技术实现或合并冲突。
- 自行使用 Compose 项目 `renshi_w5` 建隔离 MySQL/Redis，生成未提交的本地 `.env`，安装依赖并创建测试库。
- 浏览器验收使用专属端口 `8105`；大批量薪酬测试也必须在本窗口隔离数据中执行。
- 不连接或修改生产财务/银行/薪酬数据；外部凭据和不可逆生产动作必须单独请求授权。

## 隔离边界

建议 worktree：`F:\renshi-w5-hr13-15`
分支：`codex/w5-hr13-15`

只主动修改 `hr_title/**`、`hr_appointment/**`、`hr_payroll/**` 及专属 UI/测试/migration。不得直接修改 HR03/09/11/12/16 内部模型，不改 settings、根 URL、共享 shell 和 CI。所有输入通过 public/Provider 快照消费。

## HR13 施工队列

1. 冻结申报批次、资格条件、材料、专家、回避、评分/投票、公示、异议、正式结果状态机。
2. 资格与业绩只消费 HR03/09/10/12 证据快照，不复制上游真值。
3. 专家分配、匿名评审、回避和投票具备 tenant、权限、审计和并发控制。
4. 公示异议有受理、调查、复核、决定、证据和时限；正式结果不可原地改。
5. 发布 `hr_title.public` 给 HR14/17/18，支持 as-of 与撤销/修订版本。
6. 拆除高维护内嵌脚本，接真实 API，补 CSP/转义、移动端、a11y 和浏览器测试。

## HR14 施工队列

1. 删除占位质量测试，以真实 Authority/Provider/权限/迁移吸收测试替换。
2. 封批次→资格→申请→评审/排名→集体决策→公示/异议→聘任→生效→任期。
3. 消费 HR12 考核、HR13 职称和 HR02 岗位容量快照；来源不可用 fail-closed。
4. 聘任生效与 HR03 Assignment、HR15 薪酬输入、HR16 离退参与方通过正式回执协作。
5. 正式聘任事实不可覆盖；续聘、解聘、调整生成新版本。
6. 并发排名/决策/生效、重复请求、wrong-tenant、权限和 outbox 重放全测试。
7. 封 HR12→HR13→HR14→HR15 联合 E2E。

## HR15 施工队列

### A. Authority 与规则

1. 建完整薪酬档案、薪资项目、规则集/版本、适用范围、期间、输入快照、计算批次、个人结果、复核、封板、差额、支付、工资条、财务对账模型。
2. 金额全用 `Decimal`；冻结舍入、税前税后顺序、规则版本、币种和生效日期。
3. 所有模型包含 tenant 与必要唯一/索引；正式结果不可原地修改。

### B. 输入与计算

4. 只消费 HR03 人员/任职、HR11 月结、HR12 考核、HR14 聘任等版本化输入快照。
5. 实现可解释计算引擎：逐项公式、依赖图、结果明细、警告/阻断、重算差异。
6. 支持批量、断点、lease、并发、幂等和失败恢复；禁止长事务包外部 I/O。

### C. 业务闭环

7. 封计算→复核→封板→支付指令→银行/财务回执→工资条→对账。
8. 封板后只允许追溯调整/差额事实，禁止直接改原工资。
9. 社保、公积金、职业年金、津补贴、扣款、个税接口采用正式 Provider 与 sandbox test。
10. SELF 工资条严格本人范围；高敏金额有独立 permission、下载水印/审计和访问追踪。
11. 完成 Legacy payroll 迁移、双跑对账、差异阈值、真冻结和恢复演练。

### D. API 与页面

12. 扩展窄 API 面，覆盖规则、期间、输入、计算、复核、封板、调整、支付、工资条、对账。
13. 已完成 UI 的每个 section 都调用真实 API；未接能力显式不可用，不用假数据填满页面。
14. 完成真实 MySQL 大批量计算、精度、并发封板、E2E 和浏览器测试。
