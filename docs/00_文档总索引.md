# 3. `docs/hr/` 是施工过程资料

这里主要有四种文件：

```text
*_GAP_MATRIX       现状与目标差距
*_TASK_TREE        阶段任务树
*_RISK_REGISTER    风险登记册
*_Sxx_*            某次阶段验收/封板记录
```

使用方法：

```text
开发某模块
→ 先看 CURRENT_STATE
→ 看对应业务总册
→ 看 GAP/TASK/RISK
→ 回到当前 main / 施工分支真实代码
→ 只按当前 Gate 验收
```

不要因为某个 `*_S13_ProductionAcceptance.md`、`FINAL_REPORT` 或历史报告写了 READY，就默认当前 HEAD 仍然 READY。

# 4. `docs/hr/legacy/` 是旧数据映射

Legacy 映射用于回答：

- 旧 Horilla 哪张表/哪个字段对应新 Authority？
- 如何迁移？
- 如何对账？
- 什么时候停止旧写？

它们不是新 Authority 模型定义。

所有旧写最终必须在 Cutover 后达到：

```text
LEGACY FORMAL WRITES = 0
```

```text
1. 当前 Git HEAD + 当前 CI / 测试 / MySQL 结果
2. CURRENT_STATE.md
3. 开发顺序_接管版.md
4. 00 全局架构合同
```
