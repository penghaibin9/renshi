# 跃科高校人事系统文档总索引

本目录是 `renshi` 的产品架构、业务设计、工程约束和生产验收资料入口。

## 文档裁决顺序

涉及“当前是否完成、是否可合并、是否可上线”时，统一按以下顺序判断：

```text
当前 main 代码与提交头
→ 当前 CI / targeted tests / MySQL migration 证据
→ 全局架构与生产 Gate
→ HRxx 模块业务总册
→ GAP / RISK / Legacy Mapping
→ 历史施工与阶段性验收记录
```

历史文件中的 `READY`、`FINAL`、旧分支名或旧状态快照不能单独证明当前代码状态。

## 3. `docs/hr/` 工程与验收资料

该目录主要保留：

```text
*_GAP_MATRIX       现状与目标差距
```

使用这些资料时，先确认它们对应的 commit / branch / Gate 是否仍与当前 `main` 一致。

## 4. Legacy 与兼容资料

仓库的上游来源与兼容治理原则统一放在：

- [`archive/upstream/README.md`](archive/upstream/README.md)

`docs/archive/` 只保存阶段性身份、旧状态、旧施工控制和来源追溯资料。它们的目标是保留可追溯性，而不是参与当前产品首页或当前完成状态判断。

## 6. 常用阅读路径

### 修改某个 HR 模块

```text
当前 main 与对应 PR
→ 本索引
→ 全局架构合同相关条款
→ 对应 HRxx 总册
→ docs/hr 下对应 GAP / RISK / Legacy 资料
→ 真实代码与 targeted Gate
```

### 修改跨域 Authority / Permission / Event / Tenant

```text
当前 main
→ 全局架构合同
→ 涉及的两个或多个 HRxx 总册
→ 迁移矩阵 / contract tests
→ MySQL 与跨域 E2E
```

### 判断能否上线

```text
当前 main
→ 当前 GitHub Actions / MySQL regression
→ GlobalProductionGateChecklist
→ Security / Tenant negative tests
→ Failure Injection
→ Backup / Restore
```

## 7. 品牌与命名

当前产品统一使用 **跃科高校人事管理与教师发展系统** 作为对外身份。

历史 `Horilla` 名称仅在以下场景保留：

- 第三方来源、许可证和版权追溯；
- 尚未迁移的内部包名、数据库对象、兼容 API；
- Legacy mapping 或历史设计文档中的必要说明。

面向用户的页面标题、Logo、帮助链接、产品说明和新文档不再以 Horilla 作为当前品牌。
