# 高校人事统一认证首校实施说明 V1

> 适用基线：V16 RepoClean + ConfigHub / Integration Hub + SSO Runtime。  
> 原则：学校认证系统只证明“你是谁”；HR03 决定教职工身份，本地权限体系决定能看什么、能做什么。

## 一、先让学校信息处确认一种登录方式

优先顺序建议：**OIDC → OAuth2 → CAS → LDAP/LDAPS**。不要同时让学校提供四套，实际有什么就接什么。

### OIDC 需要学校提供
- Issuer 或 Discovery 地址；
- Client ID；
- Client Secret（通过安全渠道提供，不放普通聊天/邮件正文）；
- 允许登记的 Redirect URI；
- Claim 字典：唯一 Subject、工号、姓名、组织；
- 测试教师账号 1 个。

### OAuth2 需要学校提供
- Authorize / Token / UserInfo 地址；
- Client ID / Client Secret；
- Token 客户端认证方式：client_secret_post 或 client_secret_basic；
- Scope；
- UserInfo 中唯一 Subject 和工号字段；
- 测试教师账号 1 个。

### CAS 需要学校提供
- CAS Server 根地址；
- Login / serviceValidate / Logout 路径；
- Service 地址登记规则；
- CAS 返回的工号属性名；
- 测试教师账号 1 个。

### LDAP/LDAPS 需要学校提供
- LDAP/AD 主机和端口；
- 必须使用 LDAPS 或 LDAP + StartTLS；
- Base DN；
- Bind DN 与服务账号密码；
- User Filter；
- 工号属性名；
- 测试教师账号 1 个。

## 二、我方给学校登记的地址

部署完成后执行：

```bash
python manage.py hr_sso_school_preflight \
  --tenant <tenant_id> \
  --connection <连接编码> \
  --public-base-url https://hr.school.edu.cn/ \
  --json-output sso-preflight.json
```

输出中的 `registration` 就是需要交给学校登记的登录/回调/退出地址。不要手工猜路径。

## 三、正式测试前必须完成

1. HR03 已有该测试教师正式工号；
2. 存在 ACTIVE EmploymentRelationship；
3. `HrAccountLink` 已唯一对应本地登录账号；
4. 外部 Subject 已人工预绑定；默认禁止首次登录自动绑定；
5. IdP/LDAP 主机已加入 `HR_INTEGRATION_ALLOWED_HOSTS`；
6. 正式环境所有 Web SSO 使用 HTTPS，LDAP 使用 LDAPS/StartTLS；
7. Client Secret / Bind Password 已通过 Integration Hub 加密保存。

## 四、上线验收只认这条链

**公开登录页 → 学校统一认证 → 学校测试账号 → 回调 → 工号匹配 HR03 → 本地账号映射 → 原权限体系 → 首页/业务页 → 单点退出。**

端点 HTTP 200、Discovery 能打开、CAS Login 能打开，都只能算“配置可达”，不能算 SSO 已上线。

## 五、最终上线门

真实测试教师至少成功登录一次后执行：

```bash
python manage.py hr_sso_school_preflight \
  --tenant <tenant_id> \
  --connection <连接编码> \
  --public-base-url https://hr.school.edu.cn/ \
  --require-live-ready \
  --json-output sso-live-ready.json

python manage.py hr_config_integration_v1_gate \
  --tenant <tenant_id> \
  --require-sso-runtime \
  --json-output implementation-gate.json
```

两条均 PASS 才能写“统一认证已验收”。

## 六、配置变更后的规则

只要修改 Adapter、Base URL、Client ID、Claim 映射、LDAP 参数，或轮换 Client Secret / Bind Password，当前 SSO 运行合同 SHA-256 会变化。之前的成功登录证据不能继续用于上线门，必须重新使用真实学校账号验收一次。

这条规则用于防止“旧环境曾经登录成功，但新配置其实没有验证”的假绿。
