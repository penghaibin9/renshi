# P3｜首次部署与人员数据迁入操作规程

适用对象：学校人事管理员与实施人员。操作原页面 `/hr/staff/`；只有具备 `hr.staff.import` 且本校 SCHOOL 数据范围的账号可批量导入。此手册不授权跨校或扩大个人权限。

## 0. 前置核对

先完成 P2：独立 MySQL 8.4、原完整依赖和历史迁移、真实登录、学校身份、组织与部门映射、静态资源和私有上传扫描。没有通过时，仅做脱敏样例练习，不导入学校正式数据。保留原库备份与源文件哈希，记录旧库版本、迁移头、操作者、批次范围、预计新增人数和允许停写窗口。

先在系统建立真实有效的本校部门。旧 Department 与 HR02 组织的映射必须在人员入职生效日有效。不能把一个部门名称随意改成某个数字来凑通过，也不能让创建组织产生伪造的正式任职。

## 1. 下载原模板，不自己造表头

打开“教职工名册”→导入区域→下载原 Excel 模板。原业务数据页叫“教职工导入”，说明/样例工作表不导入。单文件上限 5 MB、最多 5000 行，沿用原限制。

| 原字段 | 中文列 | 准备与检查 |
|---|---|---|
| staff_no | 工号 | 使用文本；前导零不丢失；同校不重复；为空时是否允许按原规则处理，不擅自填虚构工号 |
| legal_name | 姓名 | 真实姓名；同名不等于同一个人，不按姓名自行合并 |
| gender_code | 性别 | 按模板枚举，不新增未知代码 |
| birth_date | 出生日期 | 有值时必须为真实日期；不凭年龄反推 |
| document_number | 证件号码 | 文本格式；不要让 Excel 转数值或科学计数法；授权范围内收集 |
| staff_category_code | 人员类别 | 原教师/行政等枚举；不得留空冒用默认值 |
| relationship_type | 聘用关系 | 原在编/合同聘用等类别；来源应经学校确认 |
| effective_from | 入职日期 | 必须真实；不会自动补当天；批准日不当然等于生效日 |
| department_name | 所属部门 | 本校已建、有效且可唯一定位的部门 |
| legacy_department_id | 部门编号 | 有编号时与名称一致；不要自行猜 ID |

## 2. 上传后只预检

点击上传并检查“总行数、有效行、错误行、原文件行号”。此时只生成暂存任务和预检记录，不应增加 Person/Staff/Employment/Assignment。记下任务编号；上传新文件生成新任务，不可假设重复上传会自动替你排除已写入人员。

错误处理：部门不匹配→人事确认部门映射；必填缺失→返回原资料负责人；重复工号→在原名册更正或仅保留一条；日期非法→核对源文件。不要把错误值改成 0、今天、未知部门来凑数。

## 3. 明确提交有效行

确认预检结果后提交。原服务逐行原子写入，同一行的人员、主档、用工、任职和提交审计一致才算写入。某一行失败不应留下半个人；其他合法行可能已成功。一个批次部分失败时，禁止把整张原表另上传并再次批量新增。

超时/断开：先用原任务编号查状态。正在处理→不重复提交；结果不明→核对原任务；旧 worker 租约过期→使用原允许的续办入口。重复确认同一任务应回同一结果，而不是再建一人。

## 4. 下载迁入核对台账（XLSX）

本轮新增按钮位于原导入区域，取得任务后可用。接口沿用原认证及学校范围，新增：`GET /api/hr/v1/staff/import/{jobId}/receipt?format=xlsx`。系统标准路由层可能将旧前缀归一到 `/api/v1/hr/`，使用原页面产生的链接。

台账包含“迁入核对、逐行结果、错误行”三张表。按原文件行号核对同校 Person/Staff、以 `import:任务:row:行号` 为来源的用工与 PRIMARY 任职、唯一逐行审计。姓名、证件、生日、原始文件内容不进入该台账。历史自由文本错误只导出安全类别；详细字段要求在原授权任务页核对。旧 CSV 错误清单保留。

“核对一致”只表示本批已提交行的历史四层来源和审计完整。错误行仍未导入；不证明该教师今天仍在岗、已开账号、已发工资或已经通过生产验收。观察时间以后发生变化，须重新导出台账。

核对不通过：保留任务号、原文件行号、来源错误类别，请实施人员沿正式事实查原因。不能手工把台账的状态改为成功，也不能删审计或重复写主档来消除红色。

## 5. 迁入验收与切换

逐批签认源行数＝成功＋未写入错误＋仍待处理；成功行数＝四层可回读人数＝逐行提交审计数，必要时解释依法存在的历史特殊关系。核对同名两人、重复工号、第四层写失败、恢复后重复确认、未来生效、他校部门拒绝等样例。现场通过前不将“受控通过”改成“正式通过”。

切换必须有校方确认的数据冻结点、增量清单、备份、允许停写范围和回退决策人。提交后发现错误，以更正、受控追加或前向修复为主；数据库恢复会影响冻结点后的全部数据，不能当作普通撤销按钮。

实现参考：`backend/hr_staff/api/imports.py`、`services/import_service.py`、`services/import_receipt_service.py`、`import_tabular.py`。原模板及迁入制度未改写。
