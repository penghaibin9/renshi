# P5｜异常、安全和独立恢复操作卡

这是实施/运维操作规程，不由普通老师直接执行危险命令。本轮实际完成安全解压和内容指纹工具及受控测试；没有执行真实 MySQL 导出/恢复，也没有恢复客户数据库。

## A. 操作前必须确认

导出包可能含全量敏感人事资料。原 `create_school_handover_package` 导出的是**当前配置数据库与媒体目录**，不是按 school-id 自动过滤的单校导出。共库存在多个学校时，不能将整个包交给某一学校；先确定授权范围和受支持的单校交付方式。新内容指纹只核对指定学校的选定业务表，不自动证明包里没有别校数据。

日常灾备加密备份与开放格式供应商交接包不是同一用途。包、回执、密钥分别受限存放；不得放在可公开下载目录、普通工单或官网。

## B. 导出与恢复顺序

1. 校方批准演练范围、操作者、接收方、冻结点及恢复目标；核对原库只读/停写和 worker 状态。
2. 执行原只读预检，保留 MySQL 版本、迁移头、配置来源和镜像版本。不能以 SQLite 输出代替。
3. 在同一一致性点执行原交接导出和新业务内容指纹采集；期间不进行业务写入或 DDL。数据包/源指纹对应同一点，不能先导包后让业务继续写再采指纹。
4. 对包做来源渠道核验、离线 SHA256 与内部清单校验，原验证命令检查内外层 tar。相同哈希只证明字节一致，不证明发送者可信。
5. 使用**与当前配置库不同、确实为空**的 MySQL 恢复库和独立空材料目录。凭证放专用环境/秘密存储，不出现在命令行或交付包。
6. 先检查并展开材料包，再导入 SQL；恢复中的 DDL 不是一个能全部回滚的大事务。失败时保留失败日志与隔离目标，不让半恢复库启动业务。
7. 恢复后核对迁移、表/行数，切到隔离恢复库再采相同范围的业务内容指纹，比对源库指纹；额外核对材料文件字节和权限、角色查询、同一人记录与回执。
8. 保持原库未动；校方/信息中心确认演练结果后另行决定何时切换。不能因工具返回 MATCH 就宣布恢复切换完成。

## C. 本轮新增：内容级比对，不只对数量

命令为只读：`python manage.py hr_delivery_snapshot --school-id <批准的学校ID> --key-file <私有随机密钥文件> --output <全新私有JSON路径> --confirm-quiesced`。

要求原完整设置、MySQL 8.4、无已有外层事务；密钥至少32字节且仅所有者可读；输出不得覆盖已有文件，也不得放在媒体/静态资源目录。密钥从可信随机源生成，不用学校名称或生日，不写进源码。Windows上另行核验ACL。

先在原库采源指纹；恢复后以专门配置连接恢复库采恢复指纹，使用同一密钥但不同输出文件。不得把生产环境变量直接覆盖为恢复库。只采集23个指定模型，包含人员四层、导入行/审计、组织/岗位与入职模板/材料/任务/激活/回执。文件中只有模型数量、字段结构指纹和 HMAC，不输出姓名/证件/原始字段。

比对命令：`python scripts/compare_hr_delivery_snapshots.py <源指纹.json> <恢复指纹.json>`。

退出0只表示两个声明为MySQL8.4、数据库名不同的输入证据，在规定范围内结构、行数、内容摘要相同。输出始终 `release_approved=false`；并不鉴证命令真的执行过，也不覆盖全部HR18模块、私有文件内容、外部系统或签字验收。退出2表示不一致、格式损坏、同库或非MySQL证据等问题，需要核查而非改JSON。

## D. 新安全保护

重复/大小写别名/点路径别名、路径穿越、Windows设备名/ADS、符号或硬链接、特殊设备、文件与目录冲突、超多成员、超大展开内容均在写入前拒绝。单文件上限64GiB、总展开100GiB、成员20万是离线交付工具的资源保护值；超过时需重新评估交付拆分，不能临时删除检查。两个 tar 层均使用同一检查。

解压目标必须为空且私有，不覆盖其他文件。边界是防结构性危险，不代替恶意软件扫描、签名来源验证、DB权限或目标主机安全。

## E. 必做负例与三对照

| 用例 | 界面/HTTP | 数据库/文件 | 审计/结论 |
|---|---|---|---|
| 他校/学院/本人越范围 | 实际403/404，非前端隐藏 | 无越权读写 | 拒绝按原日志记录，日志无原始敏感字段 |
| 丢提交回执 | 查原请求而不是重做 | 一条业务事实 | 一次对应动作审计与同一幂等回执 |
| 第四层写入失败 | 明确失败 | 前三层不留半记录 | 无伪成功回执 |
| 旧页/任务改派 | 拒绝旧版本/原责任人 | 新职责与状态保留 | 原办理依据仍可追溯 |
| 交付包重复路径/超限 | 恢复前拒绝 | 不执行SQL | 保存失败记录 |
| 恢复后只改一行内容 | 数量可相同 | 内容摘要不同 | MISMATCH，不准靠行数签认 |
| 文件丢失/下载越权 | 拒绝或明确缺失 | 不能拿空文件冒充 | DB一致仍不能判全部恢复通过 |

参考：MySQL8.4 mysqldump官方说明 https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html；项目原 `docs/PRODUCTION_RUNBOOK.md` 与备份/交接命令的 `--help`。不得用本手册替代具体服务器演练记录。
