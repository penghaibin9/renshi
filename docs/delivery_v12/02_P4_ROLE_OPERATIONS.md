# P4｜同一名教师的跨角色办理手册

围绕同一入职单办理，不依次展示18个菜单。以下按原 HR04/05/03 路由与权限设计；具体账号、学院范围和制度由学校确认。经办、发布人、材料核验人、责任部门可以分开，不要求把所有权限给一个超级管理员。

## 角色和责任

| 角色 | 实际入口 | 必须核对 | 不能做什么 |
|---|---|---|---|
| 方案经办 | 入职管理→校本入职方案 `/hr/onboarding/school-templates` | 适用人员、日期、材料、前置任务和制度依据 | 不能发布自己参与编辑的同一版本 |
| 方案发布复核 | 同一方案页 | 实际保存内容、校方制度、校验结果 | 不替作者补写后直接自批；不能改已发布内容 |
| 人事办理员 | `/hr/onboarding/prehires` 及同单详情 | 录用条款、报到、人员匹配、模板版本 | 不用姓名猜同一个人；不重复交接成新单 |
| 材料核验人 | `/hr/onboarding/materials` | 上传件、原件或核验凭据、原因 | 上传不是核验；已核验材料不可直接覆盖 |
| 任务责任人 | 原协同任务页、HR01本人的待办 | 具体对象、前置项、本人职责、完成依据 | 不办理他人任务；不得伪造自动系统回执 |
| 人事结案复核 | 同单协同结果核对 | 四层正式记录、激活凭据、阻塞与未完事项 | 不把结案当工资支付、结束试用或所有事项完成 |
| 教师本人 | 原本人服务/授权查询入口 | 自己的申请、补件及结果 | 不授权教师读取别人的工资、证件或档案；本轮未宣称本人端全权限已实测 |

## 步骤1：配置与独立发布

经办保存学校方案草稿，处理缺少前置项、循环、枚举或日期错误，再交另一授权账号核对。发布人查看的是同一版本，不是截图或口头描述。发布成功记录版本与回执；后续修改复制新版本。停用只阻止新单绑定，旧单保留原清单。

## 步骤2：从原录用结果承接

在招聘拟录用工作台查到人，先展开实际保存的 Offer 条款。创建、审批、签发、接受及交接分别按原规则办理。内容变更时旧审批页面应被拒绝。通过服务端返回的“继续办理入职”进入同单，不手工再建第二个单据。

本轮自动回放从“已经合法接受的 Offer”受控起点开始，不代表已执行从发布招聘到考试、公示、录用的全部过程。

## 步骤3：预览绑定方案

人事办理员在校本方案页选择同一入职单，先预览适用日期、人员类别、用工性质。预览不生成任务。明确绑定后生成原任务/材料实例。已有材料、任务、正式记录或已绑定版本的单据不能偷偷换方案。

## 步骤4：报到和身份核对

从待报到列表进入详情，核对人和实际报到时间，使用原“准备报到/确认报到”动作。人员匹配冲突必须由有权人员查明，不让系统凭同名合并。进入准备激活并不等于已经写入正式主档。

## 步骤5：材料上传、核验与退回

同时选择两份所需材料，先提交第一份，再确认第二份仍在本页。上传后由核验人核验或说明退回原因；补件后重新核对。取消切换应保留当前对象和文件。离开/刷新后不承诺未上传文件可以恢复。失败时先查本行原回执，不能换文件却复用旧编号。

## 步骤6：分派与责任办理

管理人员查询本校已有办理权限的有效账号，确认分派。分派本身不授予权限。“待分派”不应出现在每个人的“我的待办”。责任人先处理前置任务，再开始和完成，提交实际说明及凭证。改派必须说明原因；原责任人随后不能继续办理。

人工完成账户开通事项，是登记人已在外部系统办妥的依据，不表示本系统已经自动连通邮箱或一卡通。自动任务仍需原提供方回执。

## 步骤7：正式激活

在同单确认材料、组织/岗位、人员匹配和适用规则。通过原激活服务写 Person→Staff→Employment→Assignment，并核对岗位额度预占的合法转换。缺材料或缺正式依据时不能激活；重复原请求不能多生成一个主档或再占一个名额。

## 步骤8：核对结果并结案

人事复核四层记录与激活依据、阻塞任务、未解决冲突。提交结案使用当前版本和内容指纹，旧页面拒绝后重新读取。非阻塞的后续任务保留原责任与状态，不批量打勾。试用状态仍服从原规则，不为结案强行回退状态。

结案回执包含对象、动作、原/新版本和待办事实；事件进入待发送队列不等于已送达外部系统。原页面链接继续到正式人员主档与任职履历。

## 常见异常的处理

| 现象 | 正确操作 | 不要做 |
|---|---|---|
| 403 无权限 | 核对当前学校、本人职责和授权，让管理员按制度处理 | 切超级管理员代替现场角色验收 |
| 旧版本冲突 | 保留填写，读取新事实、比较后明确再提交 | 删除版本参数或关闭校验 |
| 请求超时 | 使用原编号查询是否已办，核对回执 | 换新编号盲目重发 |
| 材料尚未核验 | 联系核验人补完整依据 | 直接把上传状态改“通过” |
| 结案仍阻断 | 展开阻塞原因、回到同单具体事项 | 给所有任务打勾或伪造凭证 |
| 列表没有人 | 核对筛选、分页、学校范围、同名和单号 | 从另一个学校接口拼数据 |
