# V16 — UI A 与 V15 连续源码融合

目标：把用户提供的“方案 A”视觉与 V15 真实 HR01–HR18 功能对接，而不是把离线 HTML 的虚构数据、假按钮或本地状态复制进生产系统。

## 本轮边界

- V15 仍是业务/数据库/权限/审计/状态机权威来源。
- 18 个一级模块、98 个二级菜单全部保留原目标地址，显示文案按 UI A 做短标题收口。
- 设计登记 138 个页面逐页对账：137 个由 V15 当前后端/公开门户直接承接，0 个当前页面缺失后端；另有 1 个旧设计页 R007（组织初始化）不属于 V15 当前路由且不是菜单入口，明确不回加。
- 管理端统一加载 `hr-ui-a-v16.css` 作为最后视觉层；不删除旧模块 CSS，以免破坏已验证业务控件。
- 新增菜单/页面快速搜索仅索引当前 DOM 中真实菜单链接，不调用假后端、不产生业务写入。
- 公开招聘门户同步为 UI A 视觉，但报名、查询、凭证找回仍调用 V15 原接口。
- 设计审计里曾登记的 `/hr/structure/initial-setup/` 不是 V15 当前路由，也不是二级菜单，本轮不回退补旧入口。
- 本轮未新增数据库迁移。

## 后端缺口判断

逐项核对 98 个二级菜单和 138 个设计登记页面后，V15 的当前有效页面均已有后端处理器/工作区承接；页面级矩阵见 `PAGE_ROUTE_MATRIX.*`。因此没有理由重新造一套重复后端。真正缺失的仅是视觉层和“查找模块/页面”前端能力，本轮已补齐。设计稿里的虚构人物、数字、流程按钮不视为缺失后端需求。
