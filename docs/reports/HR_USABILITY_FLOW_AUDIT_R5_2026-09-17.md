# 高校人事系统真人式流程与低学习成本整改 R5

日期：2026-09-17
基线：`Yueke_University_HR_Usability_Candidate_R4_20260917.zip`

## 1. 本轮目标

不再增加业务菜单，而是继续减少老师的重复填写、误填和“提交前自己扫整张表”的负担。R5 聚焦四件事：

1. 已有值、系统带入值必须说清来源；
2. 简洁模式不能为了少字段而把已有内容藏起来；
3. 提交前必须能一屏看到缺项和本次改动；
4. 办理助手可以知道“必填完成度”，但绝不能读取或发送表单字段值。

## 2. 已完成整改

### 2.1 提交前核对

表单顶部新增“提交前核对”。它只展示：

- 必填完成度；
- 缺失的必填字段名称；
- 本次改动字段数量；
- 系统带入字段数量；
- 本次发生改动的字段名称。

缺失项可以直接点击并跳到对应字段。

为了防止敏感信息二次暴露，核对弹窗不展示身份证、工资、手机号、联系方式、附件正文等任何字段值。

### 2.2 “已有值”和“已带入”分开

以前页面初始已有内容容易统一被理解成“系统带入”。R5 改成：

- 页面原来已有的值：`已有值`；
- 服务端显式 `data-prefill-value` 或唯一合法必填选项：`已带入`。

这样老师能知道“这本来就有”还是“系统刚替我带进来的”。

### 2.3 简洁模式只隐藏空选填项

R4 的方向是“只看必填”。R5 进一步防止过度简化：

- 空的选填项可以隐藏；
- 已有值的选填项绝不隐藏；
- 系统带入值绝不隐藏；
- 所有选填字段明确标记“可选”。

这避免了老师以为“字段没显示就是系统里没有”。

### 2.4 办理助手增加表单完成度元数据

“复制脱敏提问”现在可以附带：

- 必填总数；
- 已完成数量；
- 尚缺字段名称。

但不会附带任何字段值。因此未来接 DeepSeek / OpenAI / 校内模型时，可以回答“你还缺什么”，又不会把人员隐私带出业务页面。

### 2.5 提示词继续从“功能说明”转成“经办动作”

全模块通用问法从 8 条增加到 16 条，新增：

- 提交前帮我核对一下还缺什么？
- 哪些已有值不需要我重复填写？
- 哪些字段必须人工确认，不能自动填？
- 我只想改一项，最短怎么操作？
- 我不确定的选填项可以先不填吗？
- 这个字段为什么要填？
- 提交以后通常还要谁处理？
- 系统已经帮我带入了什么？

每个 HR01～HR18 页面现在至少有 23 个上下文问法。

## 3. 互联网研究如何使用

只吸收交互设计，不把互联网信息当学校人事事实：

- GOV.UK Question pages：只问真正需要的信息，选填项明确标可选；
- Oracle HCM Guided Journeys：把步骤指导放到当前业务任务里；
- SAP SuccessFactors Joule：用户用自然语言直接说要办的 HR 事务；
- SAP Performance Preparation Agent：给出下一步并在问题条件不足时避免武断生成结论。

互联网不会替学校自动填写工资标准、考核规则、组织岗位、合同核心条款、退休结论或个人身份事实。

## 6. 仍然不能虚报的范围

`招聘 → 入职 → 主档 → 合同 → 异动 → 资质 → 培训 → 考勤 → 考核 → 聘任 → 薪酬 → 离退 → 教职工本人服务 → 数据中心`
