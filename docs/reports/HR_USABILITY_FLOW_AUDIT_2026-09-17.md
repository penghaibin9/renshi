# 高校人事系统业务流程易用性收口记录

日期：2026-09-17  
基线：`Yueke_University_HR_Final_Source_Candidate_20260917.zip`

## 1. 本轮目标

不再增加 HR 菜单，重点降低三个学习成本：

- **找入口的成本**：不用先理解 HR01～HR18；
- **看懂流程的成本**：进入页面就知道先做什么、准备什么、下一步是什么；
- **处理错误的成本**：错误不能只说“失败/无权限/超时”，要告诉经办人员下一步怎么处理。

## 2. 实际整改

### 2.1 “菜单优先”改成“任务优先”

HR01 首页新增“我要办什么”任务入口，可搜索入职、合同续签、调动、资质到期、考核、工资核算、退休、接口同步等高频动作。搜索直接落到业务页面，不要求记 HR 编号。

### 2.2 全 HR 页面办理助手

HR01～HR18 每个模块内置：

- 页面目的；
- 建议办理顺序；
- 办理前准备；
- 常见卡点；
- 下一步入口；
- 4 个高频快捷问法。

支持 `Alt+K` 和 `/` 快捷打开，支持键盘焦点锁定、Escape 关闭、移动端全屏、reduced-motion。

### 2.3 表单第一次使用辅助

对 HR 页面现有表单自动增强，不改变后端字段和状态机：

- 自动标识 required 字段为“必填”；
- 3 个及以上必填项时显示表单完成度；
- 浏览器校验失败时集中显示“还有 N 项需要补充”；
- 点击缺失字段可以跳到对应控件。

### 2.4 错误信息改成“发生了什么 + 下一步”

统一 API 客户端新增 `apiErrorToGuidance()`：

- 超时：明确提示“先刷新状态再重试，避免重复提交”；
- 版本冲突：明确提示“刷新并核对最新状态，不覆盖他人结果”；
- 权限不足：明确提示检查角色/数据范围或联系管理员；
- 业务规则阻断：明确提示先完成前置步骤；
- 系统/提供方异常：保留 requestId，便于管理员排查。

原 `apiErrorToMessage()` 保持兼容，但输出也升级为带行动建议的文案。

### 2.5 AI-ready 提示词但不伪装成 AI

当前办理助手的页面说明是确定性规则内容，不伪装成大模型。点击“复制脱敏提问”时只生成模块/页面类型/用户问题，不读取页面可见人员数据。未来接入模型时可直接复用，并保持正式 HR 决策在后端业务规则中。

## 3. 互联网对标结论

本轮只参考官方公开资料：

- Oracle HCM Guided Journeys：把教程、政策、最佳实践嵌入具体 HCM 流程和页面区段；
- Workday Home：统一首页提供与权限相关的建议任务、交易和洞察；
- ServiceNow Employee Center：统一入口搜索答案、请求服务、完成任务；
- SAP SuccessFactors Joule：按具体业务场景提供示例自然语言问法。

因此本系统采用“任务搜索 + 页面上下文引导 + 提示词芯片 + 可执行下一步”的组合，而不是新建一个单独的帮助中心让用户离开业务页面学习。

## 4. 本轮真实浏览器验证

当前云执行环境没有 Django，且远程桌面设备未连接，因此**不能声称已经完成真实 Django/MySQL 全业务运行验收**。

但已使用当前环境真实 `/usr/bin/chromium` + Playwright 对本轮实际交付 CSS/JS 做浏览器运行验证：

- HR05 入职场景：办理助手打开/关闭、任务搜索、提示词说明、脱敏提示词、表单完成度、必填跳转全部 PASS；
- HR01 场景：“我要办什么”搜索“入职”正确落到 HR05；“退休”快捷动作正确落到退休预审，且不再混入无关 HR01 待办；
- 超时错误引导保留 requestId，并明确避免重复提交；
- 浏览器 pageerror：0。

证据目录：`tests/artifacts/hr-usability-static/`。

## 5. QA 环境的真实业务流程门已经升级

`scripts/hr_real_browser_click.py` 原本就会在真实 Django/MySQL QA 中：

- 使用真实登录表单登录；
- 从 HR01 点击进入 HR01～HR18；
- 对有明确业务入口的模块继续点击二级业务；
- HR03 用实际技术测试人员走名册→档案→任职/履历/材料/更正页面；
- 收集页面错误、HR API 错误和截图/trace。

本轮又增加：

- HR01 必须显示“我要办什么”；
- 搜索“入职”必须解析到 HR05 待报到入口；
- HR01～HR18 每个模块都必须出现上下文“办理助手”；
- 每个模块至少 4 个快捷问法；
- Escape 必须可关闭助手。

因此等 QA 服务器具备 Django/MySQL 后，真实业务点击门会同时验证“业务可走”和“新手能找到入口/看懂下一步”。
