# 高校人事系统 14 段全生命周期与低学习成本收口 R4

日期：2026-09-17

## 1. R4 目标

R4 不增加 HR 业务模块，而是把用户指定的主链真正固化为一条连续办事路线：

**招聘 → 入职 → 主档 → 合同 → 异动 → 资质 → 培训 → 考勤 → 考核 → 聘任 → 薪酬 → 离退 → 教职工本人服务 → 数据中心**。

每一步的产品原则统一成一句话：**系统负责带入已经知道的，经办老师只确认当前发生变化的。**

## 2. 已完成的产品改造

### 2.1 14 步全生命周期教练

全 HR 页面新增同一条 14 步办理路线，保存导航核对进度，支持开始、下一步、暂停、重新开始。路线只表示导航和核对，不把“点到下一页”冒充审批、核验、发薪或人事结果完成。

### 2.2 少填字段

新增 `hr-smart-fill.js`：

- 服务端明确预填值自动带入；
- 必填下拉只有一个合法选项时自动选中；
- 当前年度、明确的填报/申请/登记/记录日期时间和候选流水号可以“一键填可确定项”；
- 复杂表单首次默认“只看必填”，用户可随时显示全部；
- 已有值标记“已带入”；
- 退回后强调只修改失败/缺失项，不要求把已核验内容重新抄一遍。

禁止自动猜测：身份证、联系方式、工资金额、银行卡、资格结论、审批意见、考核结论、离退原因、生效日、实际到校时间、合同核心条款以及学校专属政策。

### 2.3 内置提示词扩容

每个模块现在至少显示 15 个上下文问法。R4 新增的重点不是“AI 聊天”，而是把老师最常问的三类问题直接做成按钮：

1. 最少填什么；
2. 哪些可以带入/沿用；
3. 退回、失败、异常时只改什么。

同时扩充口语别名：如“新入职怎么办”“老师报到”“换科室”“证书续期”“考核有异议”“退休手续”“我想改信息”等。

### 2.4 公共信息只内置可验证的通用目录

联网核对事业单位岗位设置公开规则后，确认现有 HR02 已内置管理岗位、专业技术岗位、工勤技能岗位和特设岗位；默认等级模板已有管理 10 级、专业技术 13 级、工勤技能技术工 5 级。R4 只把这些通用信息做成字段提示，实际等级、结构比例、特设岗位条件仍以学校已生效配置为准。

## 3. 成熟产品对标后吸收的原则

- Oracle HCM Guided Journeys：在具体 HCM 流程/页面上下文中嵌入教程、政策和最佳实践；R4 对应为每页办理助手和 14 步流程教练。
- ServiceNow Guided Self-Service：用可搜索的视觉问答和分步引导帮助不同经验水平的员工自助；R4 对应为“我要办什么”、口语搜索、分步下一步。
- SAP SuccessFactors Onboarding：招聘到入职的数据应映射复用，并建议入职阶段只把确实需要新员工提供的字段设为必填；R4 对应为“只填变化项”、无歧义预填和默认只看必填。

这些原则用于降低操作成本，不用于从互联网生成学校制度或具体人员事实。

## 4. 浏览器验证

使用真实 `/usr/bin/chromium` + Playwright 执行交付版 CSS/JS：

- HR05 办理助手、15+ 提示词、术语解释、脱敏提问、表单缺项提示；
- 唯一合法的必填下拉无需点击即自动带入；
- 复杂表单支持默认/手动简洁模式；
- HR01 “我要办什么”及口语搜索；
- 14 段路线按指定顺序逐步点击，href 顺序完整匹配；
- 每步有少填字段说明；
- 浏览器 `pageerror = 0`。

注意：当前 Chromium 走查验证的是交付前端的导航、上下文和少填逻辑，不冒充真实 Django/MySQL 业务事务。脚本证据明确记录 `backend_business_transactions_executed=false`。

## 5. 运行边界

当前执行器实际执行 `python manage.py check` 仍返回 `ModuleNotFoundError: No module named 'django'`；Remote Desktop Commander 当前设备离线。因此招聘创建、拟录用、报到、正式主档写入、合同签订、异动生效、工资封板等真实事务仍必须在有 Django + MySQL 的 QA/学校环境执行。

真实 QA 脚本 `scripts/hr_real_browser_click.py` 已同步升级：每个 HR 模块必须有办理助手、至少 15 条上下文提示和 14 步流程教练，否则真实运行门失败。
