# 高校人事系统业务流程易用性收口 R3

日期：2026-09-17

## 结论

R3 不再增加业务模块，继续解决“功能已经有，但普通人事老师不懂系统术语、遇到空白/报错不知道下一步”的学习成本问题。

本轮在 R2 的任务搜索、跨模块办理路线、快捷问法、表单完成度基础上继续增加：

1. HR01～HR18 上下文术语解释；
2. 26 个高频 HR/系统词汇的大白话定义；
3. “封板是什么意思”等自然语言术语搜索；
4. 空状态、错误状态、不可用状态、无权限状态的行动指引；
5. 明确区分提交/审批/核验/生效/归档，防止把中间状态当正式结果。

## 为什么这样做

Oracle HCM 的 Guided Journeys 将教程、政策和最佳实践直接嵌到 HCM 流程页面或页面区段，而不是要求用户离开当前业务去查手册。Oracle Journeys 也把多个参与者的任务组织成业务旅程。SAP SuccessFactors Joule 公布的 HR 用例使用自然语言 sample prompts 帮助用户导航或执行 HR 任务。ServiceNow Employee Center 强调从一个入口寻找答案、申请服务和完成任务。

跃科本轮没有复制这些产品，而是把相同的低学习成本原则落到高校 HR01～HR18：任务语言优先、上下文帮助、完整办理路线、术语翻译和下一步指引。

## 本轮边界

- 术语解释不推断任何具体业务对象的状态；
- “提交成功”永远不自动等同于“正式生效”；
- 办理助手不读取页面人员姓名、证件、联系方式、工资或附件正文；
- 权限、审批、核验、考核、薪酬和人事正式结论仍由后端规则确认；
- 不为了减少步骤绕过状态机、历史版本、审计和高风险二次确认。

## 浏览器验证

使用真实 Chromium + Playwright 验证交付版 CSS/JS：

- HR05 办理助手打开/关闭与键盘快捷键；
- 任务搜索与跨模块路线；
- 上下文“核验”术语解释；
- 搜索“封板是什么意思”返回大白话解释；
- 提示词脱敏；
- 表单完成度与缺项跳转；
- HR01 六类高频口语业务搜索；
- 浏览器 pageerror = 0。

完整 Django/MySQL 业务运行门仍必须在具备运行依赖的 QA 环境执行；当前沙箱没有 Django，Remote Desktop Commander 复查时也没有在线设备，因此本报告不冒充运行期验收。

## 最终封包复核

第一次 R3 反向解压验货发现封包脚本使用字符串 `lstrip` 处理相对路径，会把 `.env.dist`、`.dockerignore`、`.github/...` 的前导点错误剥掉。该第一版 R3 包已废弃，没有作为交付版。

最终 R3 改为使用 `Path.relative_to()` 保留原始相对路径，并从最终 ZIP 重新解压确认：`.env.dist`、`.dockerignore`、`.gitattributes`、`.github/workflows/...` 均原名存在；Manifest 10698/10698，缺失、额外、哈希/大小错误均为 0。
