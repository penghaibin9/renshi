# V8 验收边界与尚未完成项

## 本轮真实执行

215项薪酬测试、9项招聘测试；36项浏览器检查；新迁移9项SQLite演练。测试结果不是相加后的同等数量完整端到端流程。HR15是实际SQLite ORM落表，不再只是静态截图；但不是MySQL。

浏览器策略阻止地址导航，实际使用原Django模板及原JS/CSS的set_content渲染，加显式Python HTTP传输桥接到本地实际Django接口与SQLite。金额、试算、复核、冻结、正式核算、Excel草稿实际经接口保存；没有用写死JSON伪造这些结果。身份/权限成员来源与全局壳层是明确测试夹具；生产登录、完整导航、真实网络TLS、Cookie认证仍待验收。缺CSRF令牌被实际中间件拒绝。

付款测试使用明确的可信测试提供方，不是银行连接，也没有验证真实签名机构。税账根据提供方回执在本地更新，不是税局正式申报。1093×614 @1.25是等效视口，不是Windows系统设置实际125%。

新迁移0014确实执行并回退演练，但旧0011含MySQL特有触发器；演练仅跳过那两条RunSQL，原工程文件未改。旧字段内容校验保留、新默认值、空功能反向重放、存在事实时拒绝回退已测；不证明MySQL建表、触发器或事务隔离已通过。

## 明确未完成

1. 完整MySQL历史迁移、真实并发锁、生产同构启动、银行/财务/税局外部联调、学校实际工资签认。
2. 非居民、劳务特殊预扣与协定；复杂跨月到账税务更正、跨年特殊补税；负向追扣和复杂社保反算。本轮遇到这些场景明确阻断，不默认0，不假称对账成功。
3. 校院两级预算分配、年度绩效预发清算、完整教务科研接口及复杂工作日/校历计付。已有受控工作量核定与公式基础，不等于完整专项系统。
4. V7记录的HR05协同任务办理、入职姓名搜索、Offer跨角色内容回读、材料逐行连续上传等没有在本轮全部实现。不能因为增加了工资引擎就宣布HR01—HR18所有业务都做深。
5. 万人规模性能、Windows实机/原生文件选择器/打印，及完整院系级/本人数据范围穿透未完成。

## 部署前必须区分

学校没提供的工资标准、制度、缴费参数和实账样本，是参数及验收缺口；复杂负向/特殊税务等是尚未实现的代码范围；MySQL、真实登录、外部支付是验证/集成缺口。三者不能都写成“只差配置”。
