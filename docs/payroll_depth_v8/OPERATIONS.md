# V8 操作与独立预发布说明

## 1. 新手办理顺序

1. 人事确认原HR03四层正式人员、用工关系和主岗；在原HR15维护主发薪身份与工资组。一个人不能因为有两个主岗就自动重复领基础工资。
2. 打开“工资制度与核算”。在制度与标准页建立工资组适用制度、岗位/薪级标准、工资项目规则，填写依据、生效日和适用来源。未生效草稿不参与计算。
3. 由另一位有原HR15复核权限的人核对并发布。看到等级、金额和依据后再确认；不能只看编号批准。已发布事实不可无痕修改。
4. 在人员核定页选择教职工、主发薪身份、正式用工关系，核定岗位工资等级、薪级、变量、地区、成本分摊和税务扣除。当前无收入或无余额也要有明确依据，未知不是零。
5. 首次使用税账必须核对本扣缴主体下本年历史收入、扣除、已扣税及奖金是否已经使用；系统不猜测期初。
6. 建立制度期间，填写工资所属月份、预计支付日及用途。正常工资、专项补发和全年奖金不是同一个用途。先为人员试算、展开逐项金额与日期分段、下载Excel，再由另一人复核准确修订。
7. 冻结该期间输入，逐人采集已获批试算，发薪名单完整后运行原正式核算；缺人、缺标准、缺依据或已变更来源会阻断，不静默略过。
8. 到原结果工作区复核、封账；到原支付与回执区按原授权提交。试算、正式核算、银行接收和税账入账分别记录，不用一颗按钮伪装四步成功。
9. 回执缺支付日时先保留银行接受事实，待可信渠道补充并验证日期；不能由普通前端手填一个日期强行完成对账。
10. 需历史正向补差时，在本工作台选择原已正式支付结果，生成历史重算试算、独立复核，再应用差额。旧工资保留；不从前端传一个随意金额。负向、复杂缴费或跨月税务更正会明确阻断。

## 2. Excel 操作

标准、个人核定、工作量各有原应用生成的xlsx模板。下载模板 → 填写 → 上传预览 → 查看错误行 → 明确确认，确认只生成待复核草稿；由另一人发布后才影响新试算。预览有错不部分偷偷入库，重复确认不新增第二份。预览有有效期，且绑定学校、操作者和文件内容校验。

工资试算导出四张表：试算回执、逐项金额、分段依据、成本分摊。这不是银行发放文件，不是税务申报表。出口沿用权限和审计。

## 3. 配置边界

标准金额、参保比例、上下限、绩效/课酬分配方案均由学校正式文件确认。代码中测试金额只在tests里，不自动装入学校正式政策。公式仅支持受限操作树，没有eval、任意Python或SQL。普通工资只用居民工资方法；全年奖金必须走对应用途及资格核验。

制度、标准、个人核定支持已批准替代记录；新内容在自己的有效区间覆盖被替代记录，不覆盖历史原记录。分组项目公式当前使用非重叠有效日期版本，**不支持通过supersedesId原地替代已发布无限期公式**。需要复杂变更时应先设计合法新政策/项目或增加后续受控发布工具，不能直接改数据库绕过。

## 4. 更新不是前端替换

先备份现有数据库、媒体和运行配置，并在独立预发布复制库校验备份可恢复。保留原.env、密钥与外部接口配置，不使用测试settings上线。存在并行开发必须先合并差异，不把完整包覆盖到正在施工的代码上。

本轮新增迁移为 `backend/hr_payroll/migrations/0014_university_policy_depth.py`，依赖原0013；原历史迁移不改写。旧期间、原快照、旧规则分别保持LEGACY_V2、修订1和未分组规则等兼容值。

已核对原生产编排：release服务执行 `python manage.py prepare_runtime --migrate --collectstatic`。本轮沿用这个单一发布入口，不另起Web多副本同时迁移。具体启动仍沿用现有已批准的部署流程；本包没有替你在腾讯云执行。

预发布中先查看迁移计划、跑真实MySQL迁移与回归，再执行原release和静态资源收集。下列命令仅在**已经隔离的预发布环境**中由部署人员执行，不是让生产库临时采用测试配置：

```bash
python manage.py showmigrations hr_payroll
python manage.py migrate --plan
# 经确认后的原release负责实际迁移和静态资源收集
python manage.py prepare_runtime --migrate --collectstatic
```

## 5. 只读预检与独立MySQL测试入口

服务器运维账号可执行 `python manage.py hr15_policy_preflight --tenant <学校ID> --actor <实际经办ID> --period <期间UUID>`。只读检查原正式事实与公式，不创建试算、工资、付款或税账；参数不是对外认证方式，严禁给普通用户开放任意actor命令执行权限。

`hr_payroll.tests.mysql_depth_settings` 是新增的显式启用测试设置。必须连接专用测试MySQL，设 `HR15_ALLOW_ISOLATED_MYSQL_TEST=YES`，数据库名必须 `yueke_hr15_test_<后缀>`，专用账号仅允许这个测试库及其`_run`库。该测试会创建/销毁指定`_run`库；本轮没有实际运行，禁止指向客户库。

```bash
# 仅在具备独立MySQL和驱动的验收环境，按文档提供测试专用环境变量
python manage.py test hr_payroll.tests --settings=hr_payroll.tests.mysql_depth_settings --noinput
```

此设置是当前模型/服务测试，使用隔离ORM建表；**不替代完整历史迁移重放**。MySQL旧库升级、新建库、锁竞争、幂等、并发、回滚都要另做。

## 6. 回退保护

本次新迁移的反向首步会检查新工资制度、核定、试算、税账、导入或新引擎期间。一旦有这些数据，反向迁移会报 `HR15_V8_ROLLBACK_BLOCKED`，防止删表把工资事实删掉。空功能演练库可以回退再重放。

有新事实时优先前向修复；需要恢复备份，应由人事/财务/运维确认恢复点，同时核对银行已接收付款和税务历史，不能把数据库恢复当作真实付款自动撤销。不要简单反向应用补丁再把新库交给旧版运行。
