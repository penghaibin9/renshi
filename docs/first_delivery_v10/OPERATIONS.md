# 校本入职方案：实际操作说明

入口：在待报到人员页面点击“校本入职方案”，路由 `/hr/onboarding/school-templates`。先完成原部署、历史迁移，再授权本校两个不同账号：配置经办 `hr05.template.manage`，发布复核 `hr05.template.publish`。看/绑定入职单还需原 `hr05.case.view`，绑定还需 `hr05.case.create`。新权限不会自动授予全员，不允许通过分派隐式提权。

1. 经办选择“新建方案”，录入本校方案编号/名称、生效日、适用人员类别/用工性质和制度依据。截止日期不包含当天。留空适用范围表示全部，须复核确认。
2. 填写任务的真实责任角色、阻塞条件、前置任务编号、可办理/截止偏移。偏移基准沿用原系统的“任务生成时间”，不是报到日期。此编辑器生成MANUAL任务，不假装自动开通外部账户。
3. 填写材料名称/编号、必交、核验阶段、格式及单文件上限。上传不等于核验通过；发布配置不能跳过原审核。
4. 保存草稿后检查循环/缺失前置、日期、格式、说明。不能发布有错误的方案。草稿尚不产生实际任务材料。
5. 另一位有发布权限且没有参与编辑的人员读取原内容，填写实际依据后发布。任何编辑人即使后来获得发布权限，也不能自行发布自己编辑的这一版。
6. 经办搜索本校可见的入职单。只有报到前、没有绑定版本/任务/材料/正式生效关系的入职单可预览和绑定；必须有匹配的预计报到日和类别。预览只读；确认绑定才一次生成原任务/材料。不能用新配置覆盖已有办理。
7. 点击“继续分派责任任务”进入V9协同办理。方案责任角色不等于已分派具体账号，仍需原权限、真实责任人、前置事项和凭证。正式激活与结案沿用原规则。
8. 已发布方案修改：复制为新草稿，复核后发布。有效期重叠时先明确停用旧版（停止用于新单）；已经绑定旧版的单据继续旧版，不重算、不重建、不删材料任务。

失败处理：普通拒绝保留当前输入；结果不明保留原请求编号，使用“核对并重试原请求”，不得另发新命令赌是否成功。已填草稿只在当前页面内存，刷新、关闭或退出不保证保留。原服务器幂等回执不等于跨系统外部开通已成功。

历史模板：未使用新schema的版本在列表只读，不通过简化编辑器覆盖其旧条件/自动任务/阶段定义。当前编辑器不是任意流程设计器，支持范围为人员类别/用工性质、手工责任任务、材料、前置关系、期限和原有阻塞级别。
