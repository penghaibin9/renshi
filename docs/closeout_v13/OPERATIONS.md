# V13 更新与核对

## 连续更新

保留原工程目录、许可证、历史迁移和 HR01–HR18。原生生产依赖仍使用项目发布配置，不把本次隔离测试依赖打包进生产。V13 没有新增数据库迁移；从旧版升级不能遗漏已经存在的 V8 payroll.0014、V10 onboarding.0018 等迁移。发布必须同步 Python/API 和名册模板、静态缓存。

## 导入结果变化

`readbackScope` 原值保留；新增 `verificationScope` 明确包含主任职和逐行审计，`accountingIssues` 标识台账守恒异常，`readbackBlocked` 标识有界核对受阻。后者非空时 `readbackCount` 可以为 null，不能强制当零；`readbackComplete` 保持 false。旧客户端应能容忍新增字段和该显式未知状态。

正常来源记录、已结束但有完整来源的历史任职依然可核对；核对通过不是当前仍在岗、账号已开或全文件全部成功。错误行继续保留并单独处理，不自动重传成功行。超过原核对范围的历史大任务交由管理员分批调查，不删记录来满足限制。

## 备份/恢复

原加密备份格式不变；只接受既定 database.sql.enc 和 media.tar.gz.enc，校验大小、摘要、AES 身份验证及媒体成员。支持原导出格式中的一个 `.` 根目录，不允许重复根、重复路径、链接或目录冲突。

两个恢复入口都只能指向独立空库和独立媒体目标；目标不得位于正在使用的媒体、静态、源码、备份、交接和回执目录，不能是这些目录的祖先或子目录，不能通过符号路径规避。同名数据库的大小写别名也拒绝。

SQL 恢复和文件替换不是一个跨资源原子事务。数据库已恢复但媒体发布失败时，命令会失败而不删除目标中新出现的文件；保留日志，检查这个独立恢复库和暂存情况，不盲目重跑非空库。恢复账号只应有目标独立库权限；不得使用有权改生产库的高权限账号。压缩包安全检查不是任意 SQL 的沙箱。只接收经授权的可信备份。

整库备份仍不等于单校过滤；23 模型指纹不覆盖全系统、全部物理表结构、索引/触发器、文件字节、外部回执和客户签字。大包容量与恢复性能仍需实际演练。

## 内容指纹 v2

新 `yueke.delivery-content-proof.2` 纳入字段长度、精度、空值、主键等字段定义，同时严格核对学校、范围、时间、哈希格式和 23 模型完整性。

v1 与 v2 不混比，不改旧文件头骗成新版本。使用 V13，在同一维护/备份点，对源库和独立恢复库分别重新采集。使用同一随机核对密钥；密钥文件须为私有常规文件（Linux 仅属主可读写，32–4096 字节），不要进入源码或客户包。两个 JSON 输出均用全新路径；不覆盖旧证据或 .env。

原采集入口 `hr_delivery_snapshot --school-id ... --key-file ... --output ... --confirm-quiesced` 仍要求真实 MySQL 8.4 与明确维护点。对比脚本 `scripts/compare_hr_delivery_snapshots.py` 即使内容匹配，缺少 MySQL 证据或同名源/恢复库仍输出 BLOCKED。退出 0 仅表示所提供文件结构/内容匹配，永远不代表已经实际恢复、证明收集人身份或批准发布。

本轮私有权限和独占写入在 Linux 文件系统测试；Windows ACL、网络文件系统与实际容器挂载行为另验。证据 HMAC/摘要不是第三方签名，也不能证明元数据声明真实。

## 回退

代码补丁回退与业务数据回退分开。优先前向修复，不恢复旧的假成功判断或弱恢复保护。保留全部老业务事实和证据；不删除业务记录配合旧代码。已发布后需回退时先暂停相关写入、核对并行变更和正在执行任务，经授权决定。
