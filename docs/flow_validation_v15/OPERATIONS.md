# V15 核心业务流程复验说明

本轮证据分三层：

1. **代表业务链回放**：每条 C01–C14 选择能够跨服务/ORM/状态机的代表测试，验证正式对象如何推进；不是把单元测试数量冒充业务流程数量。
2. **模块回归**：对可在当前隔离环境启动的 HR02–HR18 测试集合做回归；依赖 MySQL、完整生产设置、DRF 的入口保持环境门。
3. **生产门**：MySQL 8.4、真实学校登录/数据范围、原生浏览器、文件存储和外部提供方必须在独立演示环境重跑。

## 本轮产品改动
- HR06：借调/挂职创建阶段提前核对计划生效日的有效主岗与同关系 FTE，冻结临时 FTE；不删除 HR03 的 1.50 总 FTE 上限。
- HR10：创建培训申请时锁定 offering，和已锁定项目/人员一起在同一事务中核对。
- HR10→HR09：权威发展事实读取在无法证明身份 lineage 时返回 unavailable，而不是“OK 空集合”。

## 不应怎样解读
- `PASS_ISOLATED` = 当前 Django/ORM 隔离环境中的业务代表路径通过，不等于腾讯云 MySQL/生产账号已通过。
- `PASS_WITH_FIX` = 本轮先复现真实代码问题、修改后重跑代表链和模块回归通过。
- `PARTIAL_ENV_GATE` = 已验证可执行部分，但正式写回、MySQL 触发器/并发或完整设置仍有未执行部分。

详细状态见 `FLOW_RESULTS.json`。
