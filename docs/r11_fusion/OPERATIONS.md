# V14 归档证据操作说明

## 部署

沿用人事原完整发布配置、依赖和新数据库安装入口。先在独立演示环境执行正常迁移；新增 `hr_assessment.0028_archive_evidence_access`。旧迁移全部保留，不引入R11的Alembic迁移。新增一张归档访问审计表和专用权限元数据；MySQL路径还安装4个归档/审计不可修改触发器，其真实数据库执行未在本轮验证。

生产完整配置初始化当前仍缺environ；没有Docker/MySQL。不能用测试设置、迁移禁用或SQLite代替正式迁移验收。

## 授权

查阅和单份比对使用原 `hr.assessment.archive_manager` 或 `hr.assessment.auditor`；导出另需 `hr.assessment.archive.export`。沿用原账号/学校上下文，不自动给任何角色新权限。教师本人、学院账号不会因为有一个新按钮就自动获得校级证据权限。

## 六步办理

1. 用合法来源与原考核流程形成正式结果。新版本在定稿时绑定当期人员/周期/规则/来源，不能等到归档时从实时数据补写。
2. 原告知、送达、本人确认、异议处理等门禁仍执行；满足原条件后使用原“核验条件并正式归档”。
3. 在“考核管理 → 结果归档”原页面找到人员，选择已存在归档版本，填写查阅用途，再点“查看历史依据”。
4. 看归档得分、等级、当期姓名/周期、来源版本、资质附件版本及缺口。旧v1资料未冻结就显示缺口，不伪造历史。
5. 获独立导出权限后点“导出当期证据 XLSX”，得到归档说明、结果与规则、来源版本、附件版本、纪要与缺口五张表。它不是全校数据备份。
6. 展开“与一份人工核算样本比对”，填样本依据编号、人工分数和等级。只判断该份样本一致/差异/不可判定，绝不改变正式结果、规则或更正链。样本改变会清除旧判断。

## 真实边界

HR09资质来源本轮增加附件版本元数据；并未引入完整不可变文件仓库，也没有用HR09的摘要记录冒充文件字节验证。新HR12审定纪要下载会校验原私有文件的大小/摘要/类型，返回同一份已核验字节，继续使用原权限和审计。

旧档案不自动升级为v2；缺人名/证书版本就如实显示。合法结果更正产生独立结果版本；页面标注“更正结果与原计算依据”，不会声称更正分数由原公式重算得到。

读取失败不继续显示上一份证据；审计不能保存则不发送档案或导出文件。敏感草稿只在页面内存，不写localStorage。

## API

- GET `/api/v1/hr/assessments/results/{id}/archives/{version}/evidence`
- GET `/api/v1/hr/assessments/results/{id}/archives/{version}/evidence.xlsx`
- POST `/api/v1/hr/assessments/results/{id}/archives/{version}/compare`

均要求原登录/学校权限，并带 `X-HR-Access-Reason`；POST沿用CSRF，body仅 `sampleRef`、`expectedScore`、`expectedGrade`。读取拒绝/缺口不返回其他学校数据，不开放原文件存储路径。

## 回退

没有新证据时在独立环境演练反向迁移；已有访问审计或v2归档后，反向迁移明确拒绝删除这些事实。优先前向修复，不清库、不删旧档案、不通过fake迁移伪造成功。源码回退与业务数据恢复是不同工作。
