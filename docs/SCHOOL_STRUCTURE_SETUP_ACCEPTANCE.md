## 学校实际办理

学校管理中心 → 组织机构 → 建立初始组织与岗位 → 填写真实组织编码、部门、岗位目录、
岗位编码和工作量 → 明确确认 → 保存 → 正式组织树/岗位台账回读。
本入口是 `/hr/structure/initial-setup/`，无需人工 SQL、无右侧通用录入抽屉。

只适用于没有组织、岗位目录、岗位历史的空学校。一次创建学校根组织、一个真实部门、
一个岗位目录版本和一个空缺岗位，今日生效。已有记录必须返回正式工作区办理调整，
不允许重置、静默接管或删除旧数据。学校名称取本校资料；请求中的 tenant_id 无权改变目标学校。
不创建教师、不设置任职、不替代编制方案审批、不自动发布考核薪酬制度。

## 代码边界

- `hr_structure/initialization_forms.py`：明确字段白名单、编码、类别、工作量、确认。
- `hr_structure/initialization_views.py`：完整页面 + CSRF + 本校权限 + 限时办理凭证。
- `hr_structure/services/initialization.py`：复用 OrganizationChangeService、PostCatalogService、PositionService。
- `HrSchoolStructureInitialization`：每校唯一的办理回执；仅引用正式版本，不建立第二套组织或岗位主数据。
- 迁移 `0009_hrschoolstructureinitialization`：新增回执表，无历史业务回填，无历史迁移改写。
- 学校行锁串行化首次办理；根组织创建服务共用已存在学校行锁。相同请求返回原回执，
  不同内容返回 409；版本、关系、岗位、outbox、回执及审计同一事务提交。
- 正式组织树转义名称和编码，避免新增真实录入入口把普通文本当作可执行 HTML。

## 权限与失败规则

本校账号须具有组织查看/新建、岗位目录查看/管理、岗位查看/管理权限；
学校设置页另外要求学校资料查看权限。只读账号不能提交，平台支持账号不能代替
学校管理员确认初始数据；即使超级管理员也必须有该学校的明确授权。

未完善学校资料、已存在历史数据、凭证过期或学校更名时，不创建部分记录。
服务或审计失败必须全回滚，允许纠正后重试。创建后通过原 HR02 selector/API 回读，
岗位占用继续来自 HR03，不在浏览器填入“已占人数”。
