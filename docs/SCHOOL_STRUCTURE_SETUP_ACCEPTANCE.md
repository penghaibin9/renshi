## 学校实际办理

学校管理中心 → 组织机构 → 学校首次建立组织与岗位 → 填写本校真实组织编码、
首个部门、岗位目录、岗位编码和工作量 → 明确确认 → 保存 → 正式组织树/岗位台账回读。
本入口是 `/hr/structure/initial-setup/`，无需人工 SQL，不使用右侧通用录入抽屉。

只适用于没有组织、岗位目录、岗位历史的空学校。一次创建学校根组织、一个实际部门、
一个岗位目录版本和一个空缺岗位，今日生效。已有记录必须返回正式工作区办理调整，
不允许重置、静默接管或删除旧数据。学校名称取本校资料，请求中的 tenant_id 无权改变目标学校。
不创建教师、不设置任职、不替代编制方案审批、不自动发布考核薪酬制度。

## 权限与失败规则

本校账号须具有组织查看/新建、岗位目录查看/管理、岗位查看/管理权限；
学校设置页另外要求学校资料查看权限。只读账号不能提交。即使超级管理员也必须有
该学校的明确授权，平台限时支持身份不会自动获得替学校确认首次结构的权限。

未完善学校资料、已存在历史数据、凭证过期或学校更名时，不创建部分记录。
服务或审计失败必须全回滚，允许纠正后重试。创建后通过原 HR02 selector/API 回读，
岗位占用继续来自 HR03，不在浏览器填入“已占人数”。

### 浏览器等待规则

旧共享壳在载入后调用 History API，不能把同页 URL 事件当作真实导航完成。
`click_document` 要求真实点击、目标主框架文档 GET、精确 URL、HTTP 状态和 DOM 加载；
首次提交另外核验 POST 302，不以 XHR 200、强制点击或预写数据库代替。
`scripts/school_structure_navigation_contract.py` 的四个真实 Chromium 回归覆盖
History API 干扰、POST 重定向、同 URL 的 XHR 不能冒充文档、503 不能冒充成功。

### 账号页头

无 Employee 档案的学校账号使用本地文字头像与实际账号名，不请求空图片地址，
不被错误标为人员“离线”，也不展示尚无人员身份的个人档案操作。
已有 Employee 的头像、在岗显示和个人资料权限路径保留。
`base.test_account_profile_header` 执行三个模板回归，组织办理的三个普通账号登录后
还要实际核验页头身份与头像，不能只检查静态 HTML 字符串。
