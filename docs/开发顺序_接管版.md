# 开发顺序（生产收口版）

> 更新日期：2026-09-04  
> 适用范围：`penghaibin9/renshi` 当前 `main` 之后的全部生产收口施工  
> 目标：不再横向增加业务面，按同一黄金教职工生命周期把 HR01～HR18、MySQL、权限、审计、浏览器和运维证据收成一个可交付系统。

## 0. 施工总原则

```text
先修门禁和真相
→ 再封岗位与人员地基
→ 再打通招聘到正式在岗
→ 再接通任职期间业务
→ 再打通职称聘任薪酬离校
→ 再做跨角色浏览器与负例
→ 最后做恢复、发布和 Release Seal
```

强制规则：

1. 同一时间只允许一个活动施工阶段、一个主施工分支、一个主 PR。
2. 当前阶段存在红灯时留在本阶段修复，不跳关，不开新模块施工线。
3. 不以页面数量、提交数量或文档篇数计算进度，只以可复现 Gate 计算。
4. 不使用 `git add -A`，不 force push，不直接在 `main` 施工。
5. 业务代码、迁移、权限、公共 API、公共状态枚举、工作流同时改动时，必须在同一 PR 中说明影响链和回归范围。
6. 所有生产结论必须绑定 40 位 exact SHA；`latest`、分支名和截图不能单独签字。
7. SQLite/PostgreSQL 可用于辅助定位，但生产签字只认 MySQL。
8. 出现 P0 或阻断主链的 P1，结论立即为 `NO-GO`。

# G1｜HR02 + HR03 岗位、编制、人员与任职地基

## 目标

确保整个系统只有一套可追溯的“岗位供给”和“人员关系”事实。

## 代码范围

```text
backend/hr_structure/   HR02
backend/hr_staff/       HR03
公共 tenant / permission / audit / event 基础能力
```

## 必须完成的正向链

```text
组织建立/变更
→ Position 建立
→ HeadcountPlan/容量审批
→ PositionReservation HELD
→ 正式入职后 COMMITTED
→ 离校或合法释放后重新可用
```

```text
Person
→ Staff
→ EmploymentRelationship
→ Primary Assignment
→ future-effective / change / close
→ as-of 历史仍可解释
```

## 必测

- A 校不能读写 B 校组织、岗位、人员和任职。
- 最后一个岗位/编制被并发申请时最多一个成功。
- 主岗唯一；兼岗不能覆盖主岗。
- 调岗关闭旧 Assignment 而不是删除。
- 重放占编/释放不造成负数、超编或重复占用。
- Excel 导入具备模板、字段校验、错误行、确认、幂等和审计；失败批次不半写。
- 导出按 tenant/scope 限制并记录操作人。

## Gate

```text
HR02 MYSQL GREEN
HR03 MYSQL GREEN
HR02↔HR03 CONTRACT GREEN
TENANT / SCOPE NEGATIVE GREEN
HEADCOUNT CONCURRENCY GREEN
AS-OF HISTORY GREEN
```

## 本阶段禁止

- 不让 HR04、HR05、HR06 自建岗位名称或第二套人员关系；
- 不用前端过滤代替数据隔离；
- 不用删除旧记录实现“当前状态”。

# G2｜HR04 → HR05 → HR03 / HR02：招聘到正式教职工

## 目标

把一个真实候选人从招聘需求推进到正式主档和真实占编，前置条件、回退、重试和跨角色回读全部成立。

## 代码范围

```text
backend/hr_recruitment/ HR04
backend/hr_onboarding/  HR05
backend/hr_staff/       HR03（只通过正式激活合同写入）
backend/hr_structure/   HR02（只通过预留/提交合同写入）
```

## 强制状态链

```text
真实岗位/编制
→ 招聘需求/批次/职位
→ 候选人报名与材料
→ 资格审查
→ 考试/面试/评议
→ 拟录用审批
→ 公示无阻断
→ Offer 发出并接受
→ PositionReservation = HELD
→ HR04→HR05 handoff
→ 报到/材料/部门到岗确认
→ 入职办结与 activation
→ HR03 Person/Staff/Employment/Assignment
→ PositionReservation = COMMITTED
```

## 必测

- 无真实岗位、无可用编制、拟录用未通过、公示有阻断或 Offer 未接受时，handoff 必须拒绝。
- handoff 重放只产生一个有效 OnboardingCase。
- activation 重放不产生第二个 Staff、EmploymentRelationship、Primary Assignment。
- HR04 显示成功时 HR05 必须能回读同一 Case；HR05 显示激活时 HR03/HR02 必须形成同一事实链。
- 任一跨域写失败时事务不产生不可解释半写。
- 候选人、用人部门、人事、审批角色的数据范围严格隔离。
- 报名/入职附件经过类型、大小、恶意文件扫描、访问授权和审计。

## Gate

```text
HR02→HR04→HR05→HR03 MYSQL CONTRACT GREEN
HANDOFF IDEMPOTENCY GREEN
ACTIVATION IDEMPOTENCY GREEN
NO FAKE HEADCOUNT COMMIT
CROSS-ROLE READBACK GREEN
```

## 本阶段禁止

- 不让 HR04 直接创建正式 Staff；
- 不在候选人未激活前把 HELD 冒充 COMMITTED；
- 不靠手改数据库跳过公示、Offer 或材料前置条件。

# G3｜HR07 + HR06：合同与人事异动

## 目标

让正式在岗人员完成合同签署、生效和一次真实调岗；当前事实改变，历史和已签合同仍保持可解释。

## 强制状态链

```text
已有 HR03 EmploymentRelationship
→ HR07 合同起草
→ 审批
→ 本人确认/签署
→ EFFECTIVE
```

```text
调岗申请
→ 目标岗位容量校验与 HELD
→ 审批
→ 到生效时点关闭旧 Primary Assignment
→ 建立新 Primary Assignment
→ 目标 Reservation COMMITTED
→ 原岗位按规则释放
→ 必要时产生 ContractReviewRequired
```

## 必测

- 合同绑定已有 EmploymentRelationship，不另造人员关系。
- SIGNED/EFFECTIVE 合同不能被普通更新静默覆盖。
- 调岗失败时新旧岗位、预留和 Assignment 不得半写。
- 调岗后旧 Assignment 按 as-of 时间仍可查询。
- 已签合同保持原文；需要变化时走 review/amendment/renewal 正式链。
- 重复生效请求幂等。
- 跨租户、错误部门、错误审批人全部拒绝。

## Gate

```text
HR03→HR07 CONTRACT GREEN
HR02/03/06 CHANGE CONTRACT GREEN
SIGNED CONTRACT IMMUTABLE
ASSIGNMENT HISTORY PRESERVED
CHANGE EFFECT IDEMPOTENT
```

# G4｜HR08～HR12：任职期间资格、发展、考勤与考核

## 目标

形成可被后续职称、聘任和薪酬消费的可信过程事实，而不是手填最终标签。

## HR08 外聘

```text
外聘需求/协议
→ 身份与任务
→ IAM/教务协同入队
→ 真实回执后生效
→ 续聘/到期/退出
→ 权限与教务身份回收
```

- External Engagement 不冒充正式 EmploymentRelationship。
- Provider 不可用、回执失败或重试耗尽必须呈现风险，不能显示最终成功。

## HR09 + HR10 资格与发展

```text
资格/双师材料
→ 规则版本校验
→ 认定/复核/生效
→ 培训或企业实践
→ 过程与成果
→ 核验
→ VERIFIED DevelopmentFact
```

- 证据、规则版本、撤销、续期和历史必须可追溯。
- HR10 正式结果通过 Provider/Event 被 HR09/HR12 消费，不跨域直接改表。

## HR11 考勤请假

```text
原始考勤/请假
→ 审批
→ 异常识别
→ 更正事实
→ 周期校验
→ 月/周期封账
```

- 更正保留原始事实；封账后普通修改拒绝。
- 重复打卡、重复审批、重复月结幂等。

## HR12 年度/聘期考核

```text
PolicyVersion/Cycle
→ Population Snapshot
→ Evidence Snapshot
→ 本人自评
→ 部门/专家评价
→ 校准/复核
→ Finalized Result
→ Revision/Appeal（如有）
```

- 未定稿不能被 HR13/14/15 当成正式结果。
- Finalized 后更正必须新版本，不原地覆盖。

## Gate

```text
HR08 EXTERNAL CONTRACT GREEN
HR09 QUALIFICATION HISTORY GREEN
HR10 VERIFIED DEVELOPMENT GREEN
HR11 CLOSED PERIOD IMMUTABLE
HR12 FINAL RESULT CONTRACT GREEN
```

# G5｜HR13 → HR14 → HR15 → HR16 → HR17 → HR18

## 目标

打通教职工后半生命周期，并证明本人端和数据中心只读取正式业务事实。

## HR13 职称评审

```text
本人申报
→ 资格预审
→ 专家任务与评审
→ 委员会评议
→ 公示
→ ProfessionalTitleResult EFFECTIVE
```

专家只能处理分配给本人的任务；职称历史不能覆盖。

## HR14 岗位聘任

```text
有效资格/职称/考核输入
→ 聘任申请
→ 学院意见
→ 评议/集体决策
→ Appointment EFFECTIVE
→ 任期历史
```

职称不等于岗位聘任，两个 Authority 不得合并成同一状态。

## HR15 薪酬福利

```text
HR03/11/12/14 正式输入
→ 薪酬周期
→ 核算
→ 复核
→ Finalize
→ Payment Dispatch
→ 真实回执/对账
→ 本人可见
```

- 金额使用 Decimal。
- 追补追扣形成差额事实，不重写已 Finalize 历史周期。
- 外部支付未回执不能显示已支付。

## HR16 退休与离校

```text
Exit/Retirement Case
→ 部门/资产/IAM/财务/合同清退
→ 审批
→ EFFECTIVE
→ 关闭人员关系/聘任/账号
→ 完成结算
→ 释放岗位/编制
→ 归档
```

清退未完成不能标记最终离校；释放后岗位才可重新招聘。

## HR17 教职工服务

本人只读取自己有权查看的 HR03/07/09/12/13/14/15/16 正式事实；不自造结果，不允许 Employee A 猜 ID 查看 Employee B。

## HR18 数据中心

```text
正式源事实
→ MetricDefinition/Population/Dimension
→ as-of Snapshot
→ Report/Export
→ Validate/Approve/Send
→ Receipt
→ Correction 新版本
```

HR18 不能反向直接改 HR02～HR16 的源事实。

## Gate

```text
HR13 TITLE RESULT GREEN
HR14 APPOINTMENT EFFECT GREEN
HR15 PAYROLL FINAL/RECEIPT GREEN
HR16 EXIT/RETIREMENT CLOSURE GREEN
HR17 SELF DATA ISOLATION GREEN
HR18 SNAPSHOT/REPORT/CORRECTION GREEN
HR13→HR18 CROSS-DOMAIN GREEN
```

# G7｜Excel、文件、审计、异步与故障注入

## 目标

把学校真实批量工作和生产故障纳入验收，而不是只验单条表单。

## Excel / xlsx

每个高频批量域至少具备：

```text
下载模板
→ 列说明与示例
→ 预校验
→ 错误行回传
→ 用户确认
→ 原子或可解释分批写入
→ 幂等重试
→ 导入审计
→ 按数据范围导出台账
```

禁止 CSV 偷换 xlsx；禁止错误一行导致无解释半写；禁止导出全租户数据。

## 文件

- 扩展名、MIME、大小、恶意文件扫描；
- 私有存储与授权下载；
- 文件版本和引用关系；
- 删除/替换不破坏已归档证据；
- 日志不泄漏身份证件、工资、合同和令牌。

## 审计与异步

- 关键写入记录 actor、tenant、scope、对象、前后状态、request_id；
- Outbox/Event 可重放且有幂等键；
- Provider timeout/500/回执丢失不制造假成功；
- worker down、队列积压、死信、重试耗尽有可见风险；
- 定时任务无 tenant 时拒绝运行。

## 故障注入

至少覆盖：MySQL deadlock、最后一个编制并发、请求超时但下游已成功、重复事件、外部系统不可用、对象存储不可用、扫描器不可用、回执丢失。

## Gate

```text
XLSX BUSINESS GATES GREEN
FILE SECURITY GREEN
AUDIT TRACE COMPLETE
OUTBOX / PROVIDER FAILURE SEMANTICS GREEN
FAILURE INJECTION GREEN
```

# 失败后的精准回归

| 失败域 | 最小回归范围 |
|---|---|
| tenant / permission | 受影响角色入口 + 对象级正负例 + 导出范围 |
| HR02 | HR02 + HR04 选岗 + HR05 占编 + HR06 调岗 + HR16 释放 |
| HR03 | HR05 激活 + HR07 合同 + HR06 异动 + HR17 本人 + HR18 快照 |
| HR04/05 | 招聘开始至 HR03/HR02 激活结果 |
| HR07 | 合同全状态 + HR06 合同不可变负例 + HR17 回读 |
| HR06 | 目标容量 + Assignment 历史 + 合同复核 + 薪酬输入 |
| HR08～12 | 当前域完整状态链 + 下游 HR12/13/14/15 消费 |
| HR13/14 | 职称与聘任分离 + HR15/18 下游 |
| HR15 | 核算/Finalize/回执/追补追扣 + HR17/18 |
| HR16 | 清退前置 + 关系关闭 + 岗位释放 + HR17/18 |
| HR17 | 本人正例 + 跨员工负例 |
| HR18 | 快照/导出/回执/修正 + 不反写源事实 |
| migration | fresh DB + previous baseline upgrade + 所有受影响 app tests |
| Docker/配置 | production check + release + readiness + backup/restore smoke |

不要一个局部失败就无目的重跑全仓；先修根因、跑精准链，再跑最终全局门。

# 推荐提交边界

```text
ci: restore trustworthy production gates
fix(hr02): prevent concurrent headcount over-commit
fix(hr04): enforce offer and reservation handoff preconditions
fix(hr05): make activation idempotent and atomic
fix(hr06): preserve assignment history on effective change
fix(hr15): seal finalized payroll and receipt semantics
test(e2e): close golden staff lifecycle browser chain
docs: return repository documentation to current code truth
```

一个提交只解决一个可说明、可回滚、可验证的问题；但同一业务事务所需的模型、服务、测试和迁移不能被人为拆到互相不可运行的提交中。
