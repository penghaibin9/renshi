# 1. 结论先行

HR13 不是“上传论文 → 专家打分 → 自动给教授”。

它是高校专业技术职称从制度到正式结果的 **Evaluation & Decision Authority**：

```text
National / Regional Baseline
            ↓
Tenant Title Policy Pack + Version
            ↓
Series / Level / Track / Discipline Rules
            ↓
Application Batch + Frozen Rule Snapshot
            ↓
Applicant + Eligibility + Integrity Commitment
            ↓
Evidence Refs + Representative Works + Verification
            ↓
Department Recommendation / Material Publicity
            ↓
Peer Review / External Review / Defense
            ↓
Committee Session + Conflict Check + Ballot
            ↓
Proposed Result
            ↓
Result Publicity / Objection Window
            ↓
Final Title Result
            ↓
Archive / Filing / Certificate or Proof
            ↓
HR03 Title Projection + HR14 Appointment Eligibility
```

真正生产级必须做到“当时按哪一版规则、引用了哪些权威证据、哪些人以什么角色评了、哪些人因什么回避、会议是否满足组成规则、票决为何有效、公示是否完成、后续有没有复查/撤销”全部可追溯。

# 2. 生产级红线

- 不得把 HR14 岗位空缺直接当 HR13 评审结论。
- 不得把 HR12 年度优秀自动等于职称评审通过。
- 不得把师德门槛做成可以被科研分数抵消的普通权重项。
- 不得把论文数量、SCI/SSCI、影响因子写成全国统一硬编码前置条件。
- 不得把人才称号作为全国统一限制性申报条件。
- 不得把国（境）外经历作为全国统一限制性条件。
- 不得只统计成果数量而不保存代表性成果、贡献和来源。

- 不得把 DRAFT/SELF_REPORTED 证据用于正式结果而无显式风险。

# 3. 制度层级与版本化

HR13 只冻结“制度能力”，不把任何省份或学校当前办法永久写死：

```text
National Legal/Policy Baseline
        ↓
Province / Department Rules
        ↓
University Policy Pack
        ↓
Series / Level / Track / Discipline Rule
        ↓
Batch Frozen Snapshot
        ↓
Application / Review / Result
```

每层规则必须有：
`source_ref / effective_from / effective_to / version / status / supersedes / published_at / published_by / hash`。

# 4. 高校教师职称改革硬边界

- 一般设置初级、中级、高级，高级可分副高级和正高级。
- 高校可结合办学类型设置教学为主、教学科研等分类评价轨道。
- 师德师风必须作为首要条件。
- 突出教育教学能力和业绩、教书育人实绩。
- 推行代表性成果评价，克服唯论文、唯帽子、唯学历、唯奖项、唯项目倾向。
- 完善同行专家评议与外部专家评审。
- 学校自主评审不等于无监管，必须有标准公开、程序公平、结果公正和申诉渠道。
- 国家基本标准是底线，学校标准必须通过版本化 RulePack 承接。

# 5. 2024 职称评审全过程监管约束

- 监管对象包括申报人、评审专家、评审工作人员、评审单位、申报人所在单位。
- 系统必须支持事前、事中、事后全过程监管证据。
- 申报人诚信承诺必须形成可验证记录。
- 虚假材料、论文造假、成果不实等风险必须支持调查和诚信记录。
- 专家违规、工作人员违规、评审单位程序违规必须可登记、暂停、处置。
- 监管抽查、巡查、督查、质量评估和整改必须有正式 Case。
- 撤销职称必须形成独立 ResultRevocation，而非删除原结果。
- 评审权限被暂停/收回时，新的 Batch 必须 fail-closed。

# 6. 多学校 A0 硬边界

所有 HR13 权威数据必须 `tenant_id NOT NULL`。

必须做到：
- tenant A 不读 tenant B；
- 职称规则、专家池、批次、申请、评议、结果均 tenant-scoped；
- 外部专家可参与多个学校，但每次评审任务为独立 tenant context；
- SaaS 平台运营默认无学校职称材料读权限；
- background job 显式 tenant；
- webhook/provider callback 不能信任客户端裸传 tenant；
- signed URL tenant-scoped + 短时效；
- export 继承真实 scope；
- break-glass 需要 reason、审批和审计。

# 8. HR03 边界

HR03 权威：
`Person / StaffMaster / EmploymentRelationship / Assignment / EducationHistory / BackgroundFacts`。

HR13：
- 引用 stable staff/person ID；
- 冻结申报时人员与任职快照；
- 职称结果生效后发送 `ProfessionalTitleResultEffective`；
- HR03 形成可查询投影/事实；
- HR13 不直接 UPDATE HR03 当前字段；
- HR03 不修改 HR13 评审过程。

# 9. HR09 边界

HR09 提供：
- VERIFIED 教师资格；
- VERIFIED 职业资格；
- VERIFIED 双师型认定；
- 有效期/状态。

HR13 只引用这些事实作为 RuleEvidence。
普通培训证书不能在 HR13 被升级成教师资格或职业资格。

# 10. HR10 边界

HR10 提供：
- VERIFIED TrainingCompletion；
- VERIFIED EnterprisePracticeFact；
- VERIFIED PracticeEvaluation；
- VERIFIED DevelopmentOutput。

职业院校/应用型高校评审规则可以引用这些事实，但 HR13 不修改培训完成或企业实践评价。

# 11. HR12 边界

HR12 提供：
- FinalAssessmentResult；
- AnnualResultHistory；
- TermResult；
- VerifiedPerformanceEvidence refs。

HR13 只能消费正式结果，不得为了职称申报提高、重算或覆盖 HR12 历史。

# 12. HR14 边界

**职称 ≠ 岗位聘任。**

HR13 回答：“是否取得某专业技术职称/评审结果？”
HR14 回答：“在某轮岗位聘任中是否被聘到某岗位/等级？”

允许 HR14 以 HR13 结果作为资格门槛；禁止 HR13 通过即自动占岗。

# 13. HR15 边界

HR13 只输出正式结果、职称系列/层级、有效时间和应用标记。
HR15 决定：
- 岗位/职称相关工资规则；
- 津贴；
- 薪级；
- 追溯调整；
- 实际金额。

HR13 不算工资。

# 14. HR18 边界

HR18 读取 HR13 已生效的职称结果、批次统计、结构分布和监管口径。
HR18 不反向修改 HR13。
历史统计必须按 `as_of` 与 ResultVersion 计算，不能拿今天的当前职称覆盖往年。

# 15. 教务边界

- TeachingAssignment；
- TeachingHours；
- TeachingQualityFact；
- StudentGuidance；
- TeachingAward/TeachingResult（若教务为权威源）。

HR13 保存 EvidenceRef + Snapshot，不再造课程、课时、评教第二套真值。

# 16. 科研边界

科研 Authority 提供：
- Project；
- Publication；
- Book/Textbook；
- Patent/IP；
- Award；
- TechnologyService；

HR13 不靠标题字符串去重，不用“第一作者/负责人”一种角色覆盖所有学科贡献。

# 17. 文件边界

正式成果原文、证明、评议文书均通过 Documents Provider 管理：
- object storage private；
- virus scan；
- MIME/extension validation；
- hash；
- watermark；
- signed URL；
- retention；
- legal hold；
- access audit。

HR13 保存 document_id/hash/metadata，不长期保存裸 URL。
