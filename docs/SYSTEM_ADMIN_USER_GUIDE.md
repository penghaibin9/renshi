# 高校人事系统：系统管理零基础使用手册

## 1. 不要背菜单，先从“系统管理中心”开始

进入 **系统管理 → 系统管理中心**，在“我要设置什么”里直接输入目的：

- 开账号 / 停账号 / 重置密码
- 配角色 / 分权限
- 加学院 / 加部门 / 配岗位
- 改日期 / 语言 / 编号等基础参数
- 查日志 / 查越权
- 配邮件
- 查接口同步 / 失败重试
- 看备份、移交和上线验收能力

系统管理中心只做导航、概况、风险提示和实施引导，不复制 HR01～HR18 的业务权威。

## 2. 新学校第一次上线按 6 步走

1. **组织与岗位**：先确认学校、学院、部门、岗位目录。
2. **管理员与角色**：先复制最接近的角色模板，再裁剪权限和数据范围。
3. **基础参数**：日期、语言、编号、字典等学校级参数。
4. **邮件与真实接口**：SSO/数据中台必须在学校环境真实联调，不能拿 mock 当通过。
5. **安全与审计**：分别用系统管理员、业务人员、安全审计员验证权限。
6. **备份恢复演练**：正式上线前必须在隔离 QA/学校服务器实际恢复一次。

首页勾选只记录当前浏览器的学习/实施进度，**不代表正式验收通过**。

## 3. 账号管理

优先从账号/人员列表处理账号开通、停用、解锁和密码重置。账号停用和人员离职事实不是一回事：人员正式离退仍走 HR16；账号中心只控制登录能力。

## 4. 角色与权限

推荐顺序：

**复制模板 → 改角色名称 → 配成员 → 配权限 → 配数据范围 → 复核高风险权限**。

原则：

- 优先角色授权，不优先个人直接授权；
- 复制角色只复制 Permission，不复制成员、学校/组织数据范围和个人直接权限；
- Delete 类权限属于高风险权限，页面会二次确认；
- 系统管理员不等于业务终审人；安全审计员以只读为主；
- 能用普通角色完成的工作，不长期使用超级管理员。

## 5. 组织、岗位和业务事实边界

系统设置里的组织/部门/岗位是基础目录。正式人员任职、异动、聘任仍分别由 HR03、HR06、HR14 等权威链路形成，不能为了“方便”在设置页直接改正式历史事实。

## 6. 安全审计

重点检查：登录、账号变化、角色权限调整、敏感数据查看/导出、关键配置变化和接口异常。审计记录用于追踪责任和排障，不能作为普通业务记录随意删除。

## 7. 接口与同步

接口状态统一进入 HR18。重点看：字段映射、最近同步时间、成功/失败数量、失败原因、重试、回执和对账。**发送成功不等于对方已接收并对账成功**。

## 8. 备份与学校移交

源码已包含：生产加密备份、校验、恢复、学校开放格式移交、初始化快照和最终验收证据生成器。真正“备份可用”必须在第二空环境恢复验证；真正“学校可迁移”必须能用标准 SQL/附件/数据字典等资料在新环境恢复。

## 9. 上线前系统管理核对

至少确认：管理员账号、角色与数据范围、组织岗位、关键参数/字典、真实接口、安全审计、备份恢复、初始化快照、培训和最终验收证据。
