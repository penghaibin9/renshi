# 1. 结论先行
HR11 不是“每天打两次卡 + 请假审批”。

它是高校人员 **Time, Attendance & Absence Authority**：

```text
HR03 Employment / Assignment
        │
        ▼
Work Rule Eligibility
        │
        ▼
Rule Pack Version + Calendar Version + Schedule Assignment
        │
        ├───────────────┐
        │               │
        ▼               ▼
Raw Time Events      Leave / Time-off Requests
        │               │
        ▼               ▼
Pairing / Validation  Approval + Balance Reservation
        │               │
        ▼               ▼
Attendance Fact      Approved Absence Fact
        │               │
        └───────┬───────┘
                ▼
        Daily Time Evaluation
                │
        ┌───────┼────────┐
        │       │        │
     Normal  Exception  Overtime
        │       │        │
        └───────┼────────┘
                ▼
      Correction / Approval Ledger
                │
                ▼
         Period Close / Freeze
                │
        ┌───────┼─────────────┐
        ▼       ▼             ▼
      HR15     HR12          HR10
   Payroll   Assessment   Time Conflict
```

HR11 必须回答：

1. 这个人员今天适用哪套工作制度？
2. 适用规则来自组织、岗位、人员类别、Assignment 还是个人例外？
3. 这个规则当时是哪个版本？
4. 今天是工作日、休息日、法定节假日还是调休工作日？
5. 这个人应工作多少小时、哪个时段、是否要求打卡？
6. 教师岗是固定打卡、弹性、负向考勤还是仅请假？
7. 这条打卡来自哪台设备/哪个入口，是否可信？
8. 原始事件有没有重复、乱序、跨午夜、时区问题？
9. 系统如何从原始事件形成最终出勤事实？
10. 漏卡是不是设备故障，而不是人员旷工？
11. 迟到/早退是否在 grace period 内？
12. 课程、监考、会议、企业实践、培训是否造成合法时间占用？
13. 加班是否先申请、后发生，还是事后补报？
14. 加班时长是否满足规则、是否转为调休？
15. 某假别是否适用该人员？
16. 假期余额为什么是这个数字？
17. 申请中的假期是否先预占额度？
18. 半天/小时假如何按实际排班折算？
19. 已批假被撤回、缩短、延长时如何保留历史？
20. 销假后如何恢复排班和账户？
21. 月结后还能不能直接改昨天的考勤？
22. 改月结历史是否生成 Correction Batch？
23. HR15 拿到的是原始打卡还是已冻结时间结算事实？
24. HR12 是否只能读汇总，不得自行判旷工？
25. 今天改规则会不会污染去年考勤？

# 2. 生产级红线
禁止：

- `if no_checkin: absent = True`；
- 用一个 `is_present` boolean 作为考勤真值；
- 打卡事件直接作为 Payroll 输入；
- 设备上报一条记录就静默覆盖人工更正；
- 删除原始打卡事件；
- 补卡直接 UPDATE 原始事件；
- 教师没有行政坐班打卡就自动算旷工；
- 把教务课程表当完整工作时间；
- 把远程办公/校外工作记成请假；
- 加班只看下班后打卡时间；
- 加班申请通过就自动等于实际加班时长；
- 加班事实直接发钱，不经过 HR15 规则；
- 把调休余额和年休假余额混在一个字段；
- 假别规则写死在 Python `if leave_type == ...`；
- 一个学校的假别配置污染另一个学校；
- 国家节假日每年手工覆盖旧日历；
- 调休通知更新后重算并覆盖历史年度；
- 年休假余额只存当前数值而无 ledger；
- 请假审批通过后直接永久扣余额且无法撤销/纠错；
- RETURNED 与 REJECTED 混为一个状态；
- 已批准请假可无审计直接改日期；
- 取消已休完假期直接恢复余额；
- 长期病假/产假/停工留薪等只保存备注；
- 证明材料长期公开 URL；
- HR 管理员可以无理由下载全校病假证明；
- 定位坐标无限期保存；
- 人脸模板作为普通附件存储；
- 生物识别失败自动判缺勤；
- 外聘教师默认继承正式员工全部考勤规则；
- 多 Assignment 人员只读主岗规则而忽略例外；
- HR06 调岗后回写并改掉历史考勤规则；
- 月结以后直接 UPDATE 已冻结日事实；
- HR15 反向写 HR11 原始事实；
- Excel 导入绕过 service / policy / tenant；
- 批量补卡无审批、无理由；
- 设备 webhook 没有幂等键和签名校验；
- API 404/403 混淆解决越权测试；
- Provider 失败时自动 fallback 旧表并冒充新鲜数据；
- 为了“报表好看”制造 fake present；
- AI 自动判定旷工、病假真实性或纪律处分结论。

# 3. 国家制度与产品边界
HR11 必须将国家统一规则、地方规则、学校制度和个人适用事实分层。

```text
National Legal Baseline
        ↓
Regional / Local Rule Pack
        ↓
School Time & Leave Policy
        ↓
Org / Worker Category / Position Scope
        ↓
Person / Assignment Exception
        ↓
Effective-dated Policy Assignment
```

系统不能把某一学校当前制度硬编码为全国唯一规则。

产品内置的是：

- 法定基线的可配置模板；
- 生效日期；
- 来源和依据；
- 版本；
- 覆盖/继承关系；
- 校级实施细则；
- 地方扩展点；
- 人员适用范围。

任何法律/政策变化必须通过新 RuleVersion / CalendarVersion 生效，旧期间历史保持原样。

# 4. 工作时间与法定节假日硬边界
工作时间、休息日、法定节假日、学校寒暑假、教师弹性工作安排是不同概念。

2024 年修订的《全国年节及纪念日放假办法》自 2025-01-01 起施行，系统至少要支持：

- 全体公民法定节假日；
- 部分公民放假；
- 节假日与周末相遇的补假；
- 年度调休安排；
- 法定节假日前后调休工作日；
- “除个别特殊情形外连续工作一般不超过 6 天”等合规提示；
- 每年度国务院办公厅放假安排作为 CalendarVersion 数据来源，而不是写死永久日历。

禁止：

```text
weekday in [Mon..Fri] => working day
```

中国调休场景必须使用权威年度工作日历。

# 5. 年休假制度硬边界
《职工带薪年休假条例》覆盖机关、团体、企业、事业单位等；连续工作满 1 年的职工依法享受带薪年休假。

系统基线支持累计工作年限对应法定年休假档：

```text
满1年不满10年  → 5天
满10年不满20年 → 10天
满20年          → 15天
```

但数据库不能只存：

```text
annual_leave_balance = 10
```

必须拆成：

```text
Entitlement Rule
Enrollment
Accrual / Grant Ledger
Reservation
Usage
Adjustment
Expiry / Carry Forward
Settlement / Compensation Projection
```

法定节假日和休息日不得错误计入年休假用量。

---
# 6. 机关事业单位年休假校正
高校常存在事业单位工作人员，必须支持《机关事业单位工作人员带薪年休假实施办法》语义：

- 工作年限满 1 / 10 / 20 年后，从相应时点切换待遇；
- 探亲假、婚丧假、产假等国家规定假期不计入年休假；
- 依法享受寒暑假的工作人员存在“寒暑假与年休假”相互影响规则；
- 因工作需要未休/少休寒暑假时可能需要补足年休假；
- 不能安排年休假、应休未休工资报酬属于 HR15/财务结算权威，HR11 只输出应休、已休、未休和规则依据；
- 学校制度应保留更优待遇配置能力。

因此 HR11 必须有：

```text
SummerWinterBreakFact
AnnualLeaveEntitlementEvaluation
AnnualLeaveInteractionRule
UnconsumedLeaveSettlementBasis
```

不能把“有寒暑假”直接等于“无年休假”。

# 7. 事业单位旷工风险边界
《事业单位人事管理条例》存在连续旷工超过 15 个工作日、1 年内累计旷工超过 30 个工作日可解除聘用合同的规则边界。

HR11 只能形成：

```text
VerifiedUnexcusedAbsenceFact
AttendanceRiskCase
ThresholdEvaluation
```

并发出：

```text
UnexcusedAbsenceThresholdReached
```

给 HR07/HR16/HR03 等后续人事流程。

禁止 HR11：

- 自动解除聘用；
- 自动纪律处分；
- 因缺一条打卡就累计“旷工”；
- 在设备异常未清理、请假未对账、外勤未核验前形成终局旷工事实。

# 8. 高校教师工作制度校正
高校不能把全部教师按普通企业固定坐班模型处理。

至少支持：

```text
FIXED_POSITIVE_TIME        固定班次，完整打卡
FLEXIBLE_POSITIVE_TIME     弹性时段，记录实际工时
NEGATIVE_TIME              默认按计划工作，仅记录偏差
ABSENCE_ONLY               只管理请假/缺勤
OVERTIME_ONLY              只记录批准加班
DUTY_BASED                 按职责/任务核验，非每日坐班
HYBRID                      多种模式组合
```

典型适用：

- 行政/后勤/实验室值班人员：常用固定或轮班；
- 专任教师：可由学校制度决定负向考勤、仅请假、弹性或混合；
- 辅导员/宿管/安保：可能跨午夜、值班/轮班；
- 医务/实训中心/继续教育等：可能采用特殊轮班；
- 外聘教师：通常按 Engagement/Assignment 任务控制，不默认参加全职考勤。

“教师不打卡”必须是规则选择，不是系统漏洞。

SAP SuccessFactors Time Management 支持：

```text

Absences-Only Time Recording
```

这对高校非常关键。

```text
HrTimeRecordingProfile.recording_method
```

不得强迫所有教职工采用同一种打卡制度。

同时吸收 SAP：

- Time Off 与 Time Sheet 分离；
- absence 不冒充 attendance；
- time account / accrual；
- workflow；
- partial-day/hour request；
- manager team absence；
- period processing；
- transfer/assignment 后重新评估 time policy。

# 11. Oracle 对标：Work Schedule + Absence + Time Card
Oracle Fusion Cloud 的成熟模式强调：

```text
Work Schedule
+ Absence Type / Absence Plan
+ Accrual Balance
+ Time Card / Time Events
+ Approval
+ Payroll / Project consumer
```

已批准未来请假会进入相应 time card，但删除 time card 不等于删除 absence authority。

跃科吸收：

- Schedule 是计算请假时长和出勤期望的前提；
- Absence Authority 与 Time Card 表现层分离；
- approved absence 可以投影到日考勤，但其源仍是 Leave Case；
- 删除/重建日卡不能破坏已批准请假；
- time consumer 通过 Provider 获取冻结结果，而不是直读事件表。

- 《企业职工带薪年休假实施办法》（人力资源社会保障部令第1号）：劳动关系人员年休假实施规则及折算/结算边界。
- 《事业单位人事管理条例》：事业单位人员聘用、考核及连续/累计旷工相关人事后果边界。

- Horilla Attendance 官方功能：check-in/out、biometric、geofencing、hour account、late/early、overtime、shift、Payroll/Leave integration。
- Horilla Leave 官方功能：leave types、approvals、accrual/balance、carry-forward、comp-off、team calendar、Payroll integration。
