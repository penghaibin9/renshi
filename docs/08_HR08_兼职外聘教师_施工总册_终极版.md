# 0. 五个三级模块冻结

```text
HR08 兼职/外聘教师
├─ HR08-01 外聘教师库
├─ HR08-02 产业教授与技能大师
├─ HR08-03 聘用审批
├─ HR08-04 教学与服务任务
└─ HR08-05 续聘与退出
```

五个工作区职责严格分离：

- **HR08-01 外聘教师库**：外部教师/专家身份、来源单位、能力标签、历史受聘、资格、合作关系和当前可用状态；
- **HR08-02 产业教授与技能大师**：针对产业兼职教师、产业教授、技能大师、行业导师等高价值外部人才的专项身份、任务、成果和考核；
- **HR08-03 聘用审批**：需求提出、候选推荐、资格审查、冲突/合规校验、学校审批、协议准备、入校授权；
- **HR08-04 教学与服务任务**：课程、实训、专业建设、科研合作、学生指导、师资培训、企业实践指导等任务分配、履职、验收、工作量与证据；
- **HR08-05 续聘与退出**：到期评估、续聘、角色转换、任务清算、权限回收、协议终止、账号停用、历史归档。

# 1. 结论先行

HR08 不是：

```text
Employee.employee_type = "外聘"
```

也不是：

```text
创建一个 Employee
→ 发账号
→ 选课程
→ 到期 is_active=False
```

正确的高校外聘事实链是：

```text
校内业务需求
        ↓
需要外部教师/专家
        ↓
选择/新建 HrPerson
        ↓
ExternalTeacherProfile
        ↓
ExternalEngagement（聘用/合作期）
        ↓
资格与合规校验
        ↓
HR08 聘用审批
        ↓
HR07 协议/合同签署
        ↓
Engagement ACTIVE
        ↓
ExternalAssignment[]
        ├─ 教学任务
        ├─ 实训指导
        ├─ 产业导师
        ├─ 专业建设
        ├─ 科研合作
        ├─ 教师培训
        └─ 技能传承
        ↓
必要校园权限 / Teacher Identity
        ↓
履职记录 + 成果 + 验收
        ↓
到期 Review
        ├─ RENEW
        ├─ RENEW_WITH_CHANGES
        ├─ CONVERT_ROLE
        └─ EXIT
        ↓
任务清算 / 协议终止 / 权限回收 / 历史归档
```

HR08 必须同时回答：

1. 这个外部人员是谁，学校以前是否聘过？
2. 他当前属于什么外聘类别，而不是普通正式员工？
3. 谁推荐/哪个学院提出需求？
4. 为什么要聘？
5. 哪些资格已核验？
6. 是否存在利益冲突、重复聘用、期限重叠、敏感风险？
7. 聘多长时间、承担什么任务？
8. 协议是否签署并生效？
9. 校园账号、门禁、教务教师身份应开放哪些，开放多久？
10. 是否同时在多个学院、多个任务上服务？
11. 实际完成了哪些课程/指导/成果？
12. 工作量和结算依据是什么？
13. 到期后为什么续聘/为什么不续聘？
14. 退出后账号、教务身份、门禁、数据访问是否真正关闭？
15. 历史课程、学生指导和成果是否继续保留原事实？

# 2. 生产级红线

禁止：

- 把外聘教师直接建成普通正式 Employee；
- 只用 `EmployeeType=Part-time` 表达全部语义；
- 为了登录系统强行创建完整正式人事关系；
- 一个外聘人员在两个学院兼职就创建两个人；
- 跨学校按身份证自动合并同一个自然人；
- 通过 email 作为唯一身份；
- 同一个人“退休后返聘”再新建一个自然人；
- 产业教授、客座教授、兼职教师、荣誉教授全部只靠一个字符串标签；
- 荣誉性称号和实际承担课程的聘用关系混为一谈；
- 没有起止时间；
- Work Order/Engagement 到期后账号仍可登录；
- 协议未签也开放长期权限；
- 学院审批通过即等于学校聘用生效；
- 教务系统直接反向修改 HR08 身份；
- 当前外聘单位变化导致历史课程老师单位跟着变；
- 教学任务只保存“备注：本学期授课”；
- 实际工作量直接由教师自己填写且无来源/验收；
- HR15 根据 HR08 自报工作量直接发钱且无审核；
- 退出只把 `is_active=False`；
- 账号、门禁、教务权限不回收；
- 到期自动续聘；
- 续聘直接改 `end_date`；
- 外聘协议和 HR07 主合同混成一个 Payroll Contract；
- 外聘人员获得普通员工工资、福利、考勤默认规则；
- 外聘教师看到正式员工的敏感人事数据；
- 学院 A 可以管理学院 B 的外聘教师；
- 外聘教师可以因为知道其他老师 ID 读取对方任务；
- 产业专家因参与课程就自动获得全校教务权限；
- 一个账号拥有比外聘任务期限更长的有效期；
- Excel 直接批量创建账号/权限；
- AI 自动决定某候选人“不适合聘用”；
- 历史协议/材料 hard delete；
- 用 mock 协议、mock 教学任务冒充完成。

# 3. 三家成熟 HCM 对标：共同精华

## 3.1 Workday：Contingent Workforce 与正式员工区别管理

Workday 对 contingent workforce 的公开定义强调：

- 非永久、合同制、临时、项目型、自由职业或顾问等属于非传统正式员工；
- 工作期限、合作方式和支付结构通常不同于 full-time employee；
- 外部劳动力需要独立的 workforce management 策略；
- 核心风险包括身份、权限、成本、合规、绩效和生命周期控制。

跃科吸收：

```text
Person Identity
≠
Regular Employee Relationship
≠
External Engagement
```

外聘教师必须有自己的 engagement lifecycle。

## 3.2 SAP SuccessFactors：Contingent Worker + Work Order + 多 Assignment

SAP Employee Central 1H 2026 的 Contingent Workforce Management 是 HR08 最值得参考的成熟模型。

其核心思想：

- contingent worker 与 standard employee 使用区分的人员/Job Info 处理；
- 单独 permission group；
- 外部人员只维护必要信息；
- 以 Work Order 驱动合作期限；
- Work Order 到期有通知；
- 一个人可以同时存在多个 active work order / assignment；
- 可以同时服务多个部门、多个 position；
- contingent worker 可以转换/rehire 为 regular employee，regular employee 也可以变为 contingent worker；
- 有 duplicate check；
- external worker identity 向下游系统明确标记；
- Work Order 结束要联动 position/权限/下游。

跃科直接吸收：

```text
HrExternalEngagement ≈ Work Order
HrExternalAssignment ≈ Contingent Assignment
worker_kind = EXTERNAL
```

但加入高校教学/服务任务和协议体系。

## 3.3 Oracle Fusion Cloud HCM：Person Type + Contingent Worker + Security

Oracle 使用 Person Type 区分：

```text
Employee
Contingent Worker
```

Person Type 不只是显示标签，还参与：

- 人员信息管理；
- security profile；
- 不同类型 workforce 的可见范围；
- assignment/work relationship 管理。

跃科吸收：

```text
External Worker Category
→ 权限
→ 数据最小化
→ 下游身份
```

而不是 UI 上简单显示“外聘”。

## 3.4 三家共同精华冻结

HR08 必须具备：

1. Person 身份与 Worker Type 分离；
2. 正式员工与 External Worker 分离；
3. 外聘只维护必要的人事信息；
4. 以固定期限 Engagement / Work Order 作为合作权威；
5. 一个外部人员可同时拥有多个 Assignment；
6. 权限按 External Worker 类型裁剪；
7. 到期要主动处理，而不是仅改状态；
8. 支持 regular ↔ external 的身份关系转换但不复制自然人；
9. Duplicate Match 不能自动错误合并；
10. 外部人员标识必须明确同步给教务/IAM等下游；
11. 生命周期结束必须回收访问；
12. 历史任务和事实不因退出被删除。

# 4. 中国高校制度校正

2025 年教育部等八部门《普通本科高校产业兼职教师管理办法》明确：

```text
按需设岗
公开遴选
择优聘请
协议管理
```

并将产业兼职教师界定为以兼职方式承担特定教育教学和实践创新任务的：

- 行业专家；
- 专业技术人才；
- 高技能人才等。

职业学校兼职教师制度还常见：

- 特聘教授；
- 客座教授；
- 产业导师；
- 专业带头人；
- 技能大师工作室负责人；
- 实践教学指导教师；
- 技艺技能传承创新平台负责人。

高校最新管理实践还强调：

- 师德师风/思想政治把关；
- 按需选聘；
- 学校和学院分级管理；
- 具有行业/企业/科研实际经历；
- 承担教学、专业建设、科研合作、实训指导、学徒制、师资培训等实际任务；
- 聘任和履职应有期限、协议和考核。

因此 HR08 必须比普通企业 Contingent Workforce 多出：

```text
Teaching Qualification
Ethics Review
Academic/Industry Expertise
Teaching Service Assignment
Course/Practice Task
Teaching Quality Evidence
Industry Contribution
Student Guidance
Professional Development Contribution
```

不建议用一个 enum 终结所有学校差异。


## 5.1 Worker Category

建议系统内置可扩展类别：

```text
PART_TIME_TEACHER

HONORARY_TITLE
EXTERNAL_EXPERT
PRACTICE_INSTRUCTOR
RETIRED_REHIRE_EXTERNAL
PROJECT_EXPERT
OTHER
```

## 5.2 荣誉性身份必须区分

例如：

```text

```

可能只表示称号，不自动意味着：

- 有课；
- 有工资；
- 有门禁；
- 有 OA；
- 有教务权限。

因此：

> Title ≠ Engagement ≠ Assignment。

# 6. 与 HR03 的身份边界

## 6.1 HrPerson 必须复用

HR08 不建：

```text
ExternalPerson
```

作为第二自然人表。

使用：

```text
HR03 HrPerson
```

tenant-private。

同一学校：

```text
张三曾经是正式员工
退休后成为外聘教师
```

仍是同一个：

```text
HrPerson
```

但产生新的 External Engagement。

## 6.2 不跨学校自动合并

学校 A 和学校 B 即便身份证相同：

```text
不自动跨 tenant 关联
```

保护隐私。

## 6.3 StaffMaster 投影规则

某些下游要求“教师目录里必须有 Staff ID”。

允许通过 HR03 受控服务建立：

```text
HrStaffMaster
worker_kind = EXTERNAL
```

但必须明确：

```text
regular_employee = false
benefits_eligible = false (default)
payroll_regular = false
attendance_regular = false
```

具体能力由 policy 决定。

绝不能：

```text
为登录方便
→ 假装成正式 Employee
```

# 8. 与 HR02 的岗位边界

```text

EXTERNAL_POSITION_POOL
NON_STAFFING_POST
```

或者 HR08 使用：

```text

```

规则：

- 需要正式岗位目录映射的，引用 HR02 PostCatalog；
- 不占编制的，不伪造正式空编；
- 若学校规定产业教授岗位有数量控制，可通过 External Position Pool 管；
- 不允许外聘人员消耗正式编制额度除非制度明确。

# 43. Activation

事务：

1. lock case；
2. revalidate dates；
3. confirm HR07 agreement state；
4. create Engagement；
