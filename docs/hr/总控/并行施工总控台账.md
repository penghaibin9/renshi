## 7. 全局约束速查（00 合同）

- 一个事实一个 Authority；其他域只能 Provider/Event 消费。
- 无 tenant 上下文 → fail-closed（403）；`UNAVAILABLE != 0`。
- effective-dated 统一 `[effective_from, effective_to)`；历史不拿 current 回填。
- 正式结果 FINAL/EFFECTIVE 后不可原地改，走 Correction/Revision/NewTerm。
- 跨域写只能走 source domain command API / durable event / 受控 Provider action。
- Legacy 切换：DUAL_READ_COMPARE 后才 AUTHORITY_ONLY，禁止 silent fallback。
- 目标数据库需独立验证；SQLite 只做轻量单测。
- 未经授权不合并 main、不部署生产。

## 12. 全系统 JSON 字段规范（总控冻结 · 所有窗口必须遵守）

> 目的：防止各窗口发明同义字段、混用命名风格；前端中文化时只加 label 不改机器名。
> 冻结时间：2026-08-09 08:45。**所有已开/未开窗口统一遵守。**

### 12.1 字段命名

- **机器字段名一律 camelCase（小驼峰）**：`staffId`、`effectiveFrom`、`sourceBusinessId`、`maxStaleSeconds`、`definitionVersion`。
- 禁止在 API 响应里用 snake_case（`staff_id`）。Python 内部变量可用 snake，序列化输出转 camel。
- URL 路径用全拼小写（`/workforce/summary`、`/position-reservations`）；字段可用缩写（`id`、`code`、`key`、`version`）。
- 全系统统一拼写，禁止同义字段（用 `organizationId` 就都叫这个，不混 `orgId`）。

### 12.2 机器名 vs 展示值

| 用途 | 规则 | 示例 |
|---|---|---|
| 机器名（id/status/type/code） | 永远英文，不翻译 | `"status": "ACTIVE"` |
| 展示值（中文 label） | 用成对字段 `xxxLabel` | `"status": "ACTIVE", "statusLabel": "在职"` |
| 性别/类别等枚举 | `xxxCode` + `xxxLabel` 成对 | `"genderCode": "F", "genderLabel": "女"` |

前端优先显示 `xxxLabel`，无 label 才自行映射。

### 12.3 统一 envelope（保持现状）

```json
// 成功
{"data": {...}, "apiVersion": "1", "requestId": "..."}
// 错误
{"error": {"code": "DOMAIN_REASON", "message": "中文错误消息", "details": {}, "retryable": false}, "requestId": "..."}
// 列表
{"data": {"items": [...], "total": N, "page": 1, "pageSize": 20, "hasNext": bool}}
```

- **时间**：ISO 8601（`"2026-08-09T08:00:00+08:00"`）；纯日期 `"2026-08-09"`。
- **金额**：字符串（Decimal 序列化防精度丢失），如 `"12345.67"`，禁止 float。
- **错误**：`error.code` 英文大写（程序判断用）、`error.message` 中文（用户看）。

### 12.4 状态/日期/来源统一模式

- 状态机字段：`{"status": "枚举英文大写", "statusLabel": "中文"}`。
- 日期区间：`effectiveFrom` / `effectiveTo`（`null` 表示开放结束）。
- 来源：`sourceDomain: "hr04"`、`dataBasis: "LEGACY_CURRENT_SNAPSHOT"`。
- 幂等：`idempotencyKey`；追踪：`correlationId` / `requestId`。

### 12.5 全系统约定字段（统一拼写）

```
id、tenantId、staffId、candidateId、applicationId、engagementId、caseId、positionId、organizationId
createdBy、createdAt、updatedAt、effectiveFrom、effectiveTo
status、statusLabel、version、reasonCode、idempotencyKey
sourceDomain、sourceBusinessId、correlationId、requestId、sourceUpdatedAt
```

### 12.6 前端中文化配套（配合 §11 中文切换指令）

- 模板/JS 用 Django i18n（`{% trans %}` / `{% blocktranslate %}`）或单独中文文案常量文件。
