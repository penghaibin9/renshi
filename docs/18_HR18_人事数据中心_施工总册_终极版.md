> 三级模块数量：6  
> 总体策略：**REWRITE**（接管 Horilla `report/`；保留动态报表、筛选、Pivot、Saved ReportTemplate 等技术能力；重建高校人事 Metric Registry、历史 as-of、数据质量、数据交换和正式上报 Authority）  
> 全局最高合同：`00_高校人事系统全局架构与Horilla接管合同.md`

# 1. 六工作区职责

- **HR18-01 人事数据总览**：全校/授权范围的可信人事总览、结构、趋势、生命周期和质量状态。
- **HR18-02 指标口径与专题分析**：MetricDefinitionVersion、Population、Dimension、as-of 与跨域专题分析。
- **HR18-03 标准报表与自助分析**：标准报表、受控字段/维度/Pivot、自助报表、订阅和异步导出。
- **HR18-04 数据质量与治理**：数据字典、质量规则、Finding、血缘、Steward、跨域对账与回源修复。
- **HR18-05 数据交换与共享**：Dataset、Schema、Mapping、API/File/SFTP/DB Staging、学校数据中台与回执对账。
- **HR18-06 正式上报与报送档案**：主管部门/全国教师系统/教育统计等报送定义、快照、校验、审批、提交、回执、更正和档案。

# 2. HR18 的 Authority 边界

HR18 自己拥有：指标定义、报表定义、数据集定义、质量规则、血缘定义、交换定义、上报定义、报送快照、报送审批/回执/更正/档案。
HR18 不拥有：Staff、Contract、Assessment、Title、Appointment、Payroll、Exit/Retirement 等业务事实。
任何业务数据错误必须回 HR02–HR16 修复，HR18 只跟踪 Finding/Correction impact。

# 3. 为什么不是普通 Report 菜单

普通 Report 只回答“把表查出来”；成熟 HR18 还必须回答：口径、截至时间、来源、质量、历史、权限、下钻、交换、报送、回执和更正。
因此 HR18 是 Data & Reporting Governance，不是 Excel 下载中心。

# 4. Horilla `report/` 当前基线

当前 `ReportTemplate` 主要保存用户 Rows/Columns/renderer/aggregator 布局；sidebar 按 recruitment/employee/attendance/leave/payroll/asset/pms 是否安装动态挂报表。
该能力可复用为自助报表交互层，但缺少 MetricDefinition、as-of、DataQuality、Lineage、Exchange、Submission/Receipt。
因此总体裁决：**REWRITE Authority + ADAPT 报表技术底座**。

# 5. 2025 全国教师管理信息系统校正

2025-12 教育部升级上线全国教师管理信息系统，形成教师管理、教师服务、专项业务、数据分析四位一体架构，并强调标准统一、数据集中、业务协同和平台数据对接。
HR18 必须具备标准数据、动态更新、分析、共享和正式报送能力，不能只导 Excel。

# 6. 教师管理信息化长期原则

教师信息应动态更新、形成电子档案/教师队伍大数据、支持管理决策，并与教育治理/教育事业统计等工作衔接。
HR18 落地为：一数一源、指标版本、数据质量、数据交换、上报快照和回执。

# 7. 高职商业化校正

2026 高职院校公开人事系统需求已经明确数据中台联动、全周期人事、双师、企业实践、考核、薪酬与自助。
因此 HR18-05 数据交换与共享是商业核心能力，不是“以后再加”。

# 25. HR18-01｜业务目标

人事处/领导在 10 秒内知道队伍规模、结构、趋势、流动和当前数据是否可信。

# 26. HR18-01｜统计上下文

tenant + ResolvedScope + asOf + period + timezone + MetricDefinitionVersion set + source freshness。

# 27. HR18-01｜Bootstrap

`GET /api/v1/hr/data/overview/bootstrap` 一次返回首屏指标/趋势/质量摘要，非首屏 lazy。

# 28. HR18-01｜Headcount

必须来自 HR03 effective relationship/assignment + PopulationVersion；不能 count Employee.is_active。

# 29. HR18-01｜FTE

如学校启用，和 headcount 分开；兼职折算/关系范围/rounding 明确。

# 30. HR18-01｜人员类别结构

在编/合同/外聘等只能按学校冻结口径；同一人多关系按 population/grain 避免重复。

# 31. HR18-01｜组织结构

学院/部门 as-of；组织撤并时历史组织和 current rollup 两个视图分开。

# 32. HR18-01｜岗位结构

HR02 position category/grade + HR03 occupancy + HR14 appointment；对账异常有 quality banner。

# 33. HR18-01｜职称结构

HR13 EFFECTIVE as-of；revoked/superseded 不计当前但保留历史。

# 34. HR18-01｜双师结构

只统计 HR09 正式 EFFECTIVE Recognition，不用自报技能证书替代。

# 35. HR18-01｜学历年龄

HR03 verified/authorized facts；敏感小样本保护。

# 36. HR18-01｜招聘

HR04 planned→applied→eligible→selected→offer→accepted→HR05 activated；阶段用 Authority status。

# 37. HR18-01｜入职

HR05 offer-to-report、report-to-activate、材料/协同 blockers、试用转正。

# 38. HR18-01｜合同

HR07 active/expiring/renew/non-renew/terminated；历史聘期不覆盖。

# 39. HR18-01｜发展

HR10 verified completion/practice；报名≠完成。

# 40. HR18-01｜考核

HR12 FINAL only；NO_RATING 单独统计。

# 41. HR18-01｜聘任

HR14 appointment level/category/term；PROPOSED 不计 current effective。

# 42. HR18-01｜薪酬

HR15 CLOSED payroll/employer cost；默认只有专门薪酬分析权限。

# 43. HR18-01｜离退

# 44. HR18-01｜Source Freshness

# 45. HR18-01｜Quality Banner

# 46. HR18-01｜Drilldown

# 47. HR18-01｜趋势

# 48. HR18-01｜同比环比

# 259. E2E｜质量修复

# 260. E2E｜数据中台 outbound

# 261. E2E｜Inbound

外部 reference/staging→validate/map/match→source command；无 direct write。

# 262. E2E｜正式上报

cycle→snapshot→validate→review→approve→artifact→submit→ACK_PENDING→ACCEPTED→archive。

# 263. E2E｜上报拒绝

REJECTED→errors→源修复/授权补录→CorrectionPackage→resubmit→accepted，原包保留。

# 264. E2E｜报后源更正

source ResultRevision→ReportingImpact→授权判断→CorrectionPackage。

# 265. E2E｜无 API 上报

versioned file→人工主管平台上传→上传证据/流水→reviewed receipt→archive。

# 266. Legacy｜LegacyReportMapping

旧报表只能做 current compare source；未证明历史口径不能直接升级正式 Metric。

# 268. Legacy｜ReportTemplate

# 269. Legacy｜LegacyPermission

# 270. Legacy｜LegacyCurrentQuery

识别 is_active/current work info；历史报表不得复用 current query。

# 271. Legacy｜LegacyExport

同步大导出迁 HR18 async jobs。

# 272. Legacy｜DUAL_READ_COMPARE

# 273. Legacy｜Cutover

# 274. Legacy｜Rollback

# 275. AI 使用边界
